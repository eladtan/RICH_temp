1. Executive decision

Do not merge or copy RICH’s Monte Carlo directories into STORM wholesale. Port the radiation physics semantics in small, independently validated increments while retaining STORM’s generic type system, compile-time group count, traits, error handling, manager factory, Serial/Two-Sided/RDMA manager split, and IBV/OFI/MPI-RMA communication work.

Core first

Conservative static DDMC, packet state, ghost exchange, face rates, and serial/MPI parity.

Interfaces second

IMC↔DDMC boundary laws, moving-frame correction, momentum feedback, and diagnostics.

Optional stacks last

Compton, observers, polarization, and adaptive post-processing.

Main failure mode to avoid: copying RadiationIMC_DDMC.cpp while leaving STORM’s particle serialization and RDMA buffers unchanged. RICH’s DDMC is stateful across cell and rank boundaries; missing residency/frame/bypass/pending-flux fields can yield plausible-looking but physically wrong transport.

4. Architectural differences that make direct copying unsafe

4.1 Concrete RICH types versus generic STORM types

RICH’s radiation implementation directly names Vector3D, Tessellation3D, ComputationalCell3D, Conserved3D, global ENERGY_GROUPS_NUM, and static cell energy boundaries. STORM’s RadiationIMC is templated over point, grid, cell, extensives, EOS, group count, traits, and position sampler.

Rule: no source patch may introduce RICH concrete types or ENERGY_GROUPS_NUM into STORM core headers. Every such dependency must pass through an existing or newly defined trait/concept.

4.2 Manager lineage

RICH’s current manager code reflects its own MPI/RDMA history. STORM has newer target-specific work: manager factory selection, distinct Serial/Two-Sided/RDMA paths, newer RankHandler2, registered send buffers, OFI and IBV backends, asynchronous reallocation, and recent deadlock/progress hardening.

Rule: port only the manager-facing contract needed by new physics—additional particle fields, child-packet insertion semantics, progress hooks, counters, and reductions. Never replace a STORM manager with the RICH manager.

4.3 Packet persistence across transport representations

Advanced DDMC is not a stateless shortcut. A packet can remain a grey DDMC resident over multiple events, cross ranks, carry a pending remote flux contribution, bypass DDMC for one target-cell residence, convert between lab/comoving frames, and later return to IMC. These states must survive every copy, move, serialization, reallocation, population-control operation, and communication backend.

4.4 Error and boundary semantics

RICH uses UniversalError; STORM uses StormError. Boundary APIs are already very similar, but numeric nudges differ and STORM has its own geometry checks. Treat the existing STORM boundary implementation as the base and port only missing semantics with regression tests.

4.5 Header-heavy template organization

RICH can place substantial implementation in concrete .cpp files. STORM’s generic RadiationIMC must remain visible to template instantiation. Avoid growing one monolithic header; split implementation into included .tpp units and keep non-template numerical helpers in isolated headers or compiled sources only when embedding/build rules are proven.

5. STORM behavior that must be protected

The following target behavior is presumed intentional and must be covered by “unchanged when feature disabled” tests before any radiation port:

  • Generic traits and compile-time group count. Preserve NumGroups, per-cell access traits, generic point operations, and user-supplied EOS/opacity types.
  • Manager architecture. Preserve Serial, Two-Sided, legacy/RDMA, manager-factory selection, and backend configuration.
  • OFI/IBV/MPI-RMA progress and memory-registration work. New packet fields must integrate with current raw-transfer and registered-buffer paths; no reversion to RICH communication code.
  • Negative material-energy hardening. Keep the current pre-step energy floor/restoration logic and test it with DDMC/Compton energy deposits.
  • STORM-specific ddmcMinParticleOpticalDepth. RICH’s current public parameter surface differs. Retain this target-specific gate initially, document its interaction with sigmaParticleGate, and remove or redefine it only after A/B evidence.
  • Existing PGRW implementation. Validate numerical parity; do not replace it simply because RICH splits header and source differently.
  • Existing adaptive-source API. Reconcile with newer RICH controls instead of introducing a second parallel configuration path.
  • Boundary nudge and containment safeguards. Any change must pass Cartesian and distorted-Voronoi containment tests.
  • Build defaults. All new capabilities off by default; plain IMC builds remain dependency-light.

6.1 Compact packet state recommendation

Avoid adding many independent booleans with padding. Add a compact state aggregate while keeping the existing Particle<T, Grid> signature unchanged, minimizing framework churn:

template<class PointT>
struct RadiationTransportState {
    enum Flag : std::uint8_t {
        DDMCMode          = 1u << 0,
        DDMCCellResident  = 1u << 1,
        DDMCComovingFrame = 1u << 2,
        PendingFlux       = 1u << 3
    };

    std::uint8_t flags = 0;
    PointT pendingFlux{};
    std::size_t bypassCellID = std::numeric_limits<std::size_t>::max();
#ifdef MONTECARLO_POLARIZATION
    double pendingMeanScatterings = 0.0;
#endif
};

This is safer than introducing a third particle template parameter across every manager during the physics port. After correctness is established, memory profiling can decide whether a policy-based particle type is worth the broader refactor.

9. DDMC work package: detailed implementation plan

9.1 Replace the data model before replacing behavior

STORM’s current DDMC structures contain only a cell eligibility flag, a few aggregate opacities, total rate, and simple face rates. Introduce richer types first, with no behavior change, so later PRs remain mechanical and reviewable.

  • Cell fields: eligibility and exclusion reason; group cutoff; sigmaEnergyAbs, sigmaMomentum, sigmaDiffusion, sigmaParticleGate, sigmaGroupExit; diffusion coefficient; gamma; velocity divergence; face-velocity jump; flux matrix and area sum.
  • Face fields: face/target index, kind, total/internal/boundary/DDMC/transport rates, band masses, DDMC fraction, area, both center-to-face distances, conductance, target cutoff/eligibility, oriented normal.
  • Diagnostics: explicit counters for exclusion and fallback reasons rather than one aggregate fallback counter.

9.2 Coefficient and eligibility precompute

  1. Calculate physical scattering and geometry using generic grid operations.
  2. For multigroup PGRW/DDMC, use actual Planck band integrals—not equal group weights—to find the contiguous low-frequency diffusive band.
  3. Respect both the source’s compile-time NumGroups and a runtime maximum cutoff.
  4. Separate opacity roles. Do not reuse one average for energy deposition, diffusion, momentum, particle gating, and group-exit timing unless the derivation makes them equal.
  5. Preserve STORM’s particle optical-depth gate as an additional target-specific control until benchmark sweeps justify convergence.
  6. Compute velocity divergence and maximum face jump only when the cell/traits provide velocities. Static-cell instantiations must compile without fake velocities.
  7. Finalize all local exclusions—unsupported boundaries, observer overlap, external-source interior/face gates—before exchanging eligibility to ghosts.

9.3 Ghost exchange and stable identity

Build point-indexed arrays for eligibility, diffusion coefficient, diffusion opacity, cutoff, velocity, and stable cell ID. Exchange them before constructing any local-to-remote face. Never index the local cell vector using an arbitrary ghost point index.

Stop gate: if STORM’s grid cannot provide an unambiguous owner/local-index mapping for every DDMC-adjacent ghost, do not proceed to face rates. Add that grid capability explicitly.

9.4 Conservative face rates

For two DDMC cells i and j separated by face F, use the two-sided diffusion resistance:

R_ij = d_iF / D_i + d_jF / D_j
T_ij = A_F / R_ij
lambda_i_to_j = T_ij / V_i

Do not use an unweighted harmonic mean divided only by the source-center-to-face distance. Record T_ij and validate reciprocity in debug/tests.

9.5 Unequal group cutoffs

A resident grey-band packet has no microscopic group until representation conversion. If the neighbor’s low-frequency DDMC band is smaller, split the face reaction statistically into:

  • an internal DDMC channel for the common Planck-band mass, and
  • an asymptotic transport channel for the remaining source-band mass.

The event-rate split must use source-cell truncated Planck mass. At census or conversion back to IMC, sample a frequency from the corresponding truncated Planck distribution.

9.6 Resident DDMC lifecycle

  • Define valid state invariants: DDMC mode implies cell resident and comoving-frame state.
  • Store DDMC residents at a controlled representative location; when returning to transport, sample a physically valid in-cell location.
  • Never Lorentz-transform a stale microscopic direction for ordinary DDMC-to-DDMC leakage.
  • Include census, leakage, effective/upscatter, and analytic Doppler cutoff crossing in one event competition.
  • Remove zero-weight packets before event sampling, including the case initialWeight == 0.
  • At census, reconstruct microscopic direction/frequency and return to IMC for next-step reclassification unless a formally validated persistent-census representation is adopted.

9.7 Static IMC↔DDMC interface

  • Evaluate target frequency eligibility in the target comoving frame.
  • Use the asymptotic static admission probability based on incident cosine, target transport opacity, and target center-to-face distance.
  • Rejected packets undergo diffuse-albedo reflection and remain in the IMC source cell.
  • DDMC→IMC leakage uses the detailed-balance outgoing angular density, not the ordinary cosine law used for unrelated boundary emission.
  • Use a bypass stable cell ID to prevent immediate repeated admission attempts after an invalid moving-interface correction.

9.8 Moving interface correction

  • Port the exact tabulated Wollaeger kernel with independent quadrature-convergence tests.
  • Interpolate material velocity to the face using source/target distances.
  • Use the static law for the admission decision; after admission, multiply weight by the moving factor.
  • Reject invalid/nonpositive factors and excessive |U_n|/c by bypassing DDMC for that residence—never silently replace the factor by one.
  • Split corrected weight only for local targets and within the configured split budget. A remote target carries one unbiased corrected packet because newly created children cannot be inserted directly into a ghost cell.

9.9 Energy and momentum coupling

  • Perform DDMC material absorption in the correct comoving interval, convert the deposited four-momentum consistently, and update STORM extensives only through target-safe helper functions.
  • Accumulate face-direction contributions to an integrated flux RHS.
  • For a remote admitted packet, carry a pending contribution in the packet and consume it exactly once after ownership transfer.
  • Reduce ghost contributions to owners using a peer-symmetric protocol.
  • Solve the per-cell face matrix for integrated flux; retain a documented area-weighted fallback for singular geometry and count every fallback.
  • Prove there is no double momentum update at IMC↔DDMC representation changes.

10. MPI, Two-Sided, and RDMA integration

10.1 Packet wire-layout changes

STORM’s RDMA path moves contiguous particle objects. Every new member therefore affects registered-buffer size, remote windows, reallocation, and any assumptions about trivial copying.

  • Add compile-time assertions for standard layout and trivial copyability in raw-transfer backends.
  • Add a startup cross-rank layout fingerprint covering sizeof, alignof, polarization macro, and relevant feature macros; abort on mismatch.
  • Update explicit serializer dump/load in the exact same field order and test round-trip equality.
  • Verify constructors and all reset paths initialize the full radiation state.
  • Verify population control, combing, copies, moves, send-buffer detachment, and reallocation preserve state.

10.2 Child-packet semantics

Moving-interface weight splitting and Compton residual transport create child packets. Confirm each manager’s particlesToAdd contract:

  • Children inserted locally receive unique IDs and valid local cell indices.
  • No child is inserted directly into a ghost cell.
  • Remote transfers preserve stable cell ID and defer local-only tally application through packet state.
  • Termination/accounting counters include dynamically added children without premature global completion.

10.3 Do not globally rewrite MPI utilities first

The existing generic MPI_exchange_data helper may be adequate for symmetric decomposition maps but RICH found a specific deadlock mode when peer lists are asymmetric, especially with zero-owned-cell ranks. Implement and test a DDMC-specific symmetric exchange/reduction layer first. Generalize the utility only after proving compatibility with all existing users.

10.4 Backend test order

  1. Serial manager: deterministic event-level tests.
  2. Two-Sided manager: easiest MPI debugging and reference distributed result.
  3. MPI-RMA fallback: raw layout and completion semantics.
  4. IBV backend: registration/reallocation and completion.
  5. OFI backend: provider initialization, progress, registration, and Frontier-like multi-node execution.
No backend is “covered” by another. DDMC adds long-lived resident particles, dynamically split packets, and pending owner tallies; these stress progress and buffer-lifetime paths differently from ordinary IMC.

12. Post-processing, observer, polarization, and adaptive sources

12.1 Extract generic functionality from application workflow

Port these to STORM core/optional modules:

  • finite transport lifetime distinct from source emission interval;
  • no-hydro-feedback mode while optionally retaining snapshot velocities for frame transforms;
  • observer crossing detection and energy ledger;
  • per-observer and per-group tallies;
  • generic adaptive source and group-weight interfaces;
  • optional HDF5/VTK/TXT output adapters.

Keep these outside core:

  • TDE-specific runtime configuration and filenames;
  • CER construction workflow and FLD-normalized source application unless generalized as an external-source interface;
  • photosphere pipeline and domain-specific plotting scripts;
  • job-launch/Slurm scripts.

12.2 Observer abstraction first

Define a small observer interface before porting SphericalObserver. RadiationIMC should depend on crossing/tally operations, not on output formats, Fibonacci tilings, or a specific observer shape.

12.3 Polarization convention lock

  • Document that packet weight is Stokes I and packet Q/U are fractional or absolute—choose one and never mix.
  • Document basis orientation, observer reference axis, pole fallback, and lab/comoving basis transforms.
  • Add pendingMeanScatterings to packet state and serialization before accelerated transport uses polarization.
  • Split accelerated treatment into per-step history accumulation and finalization on representation exit, preserving history across DDMC cells.
  • Test basis transversality after every direction/frame change.

12.4 Adaptive source reconciliation

STORM already exposes adaptive cell/group score controls. Compare semantics and extend the existing API rather than adding RICH-named duplicates. Required additions may include learned minimum/maximum photons, score power, per-observer/group quality snapshots, and richer cap/fallback diagnostics.

Bias gate: any capped importance-weight correction must report capped energy fraction and mark the estimator potentially biased. Do not hide caps as a performance optimization.

12.5 Measured load balance

Expose transport cost data through a neutral manager/physics interface. Do not port RICH’s decomposition driver into STORM core. A consuming application may use steps per emitted packet, source-cell charge after clamping, or other measured costs to rebuild the mesh.

13.2 Physics invariants

  • Energy ledger: material + live packets + census + escaped/observed/cutoff terms equals initial + emitted source within statistical/numerical tolerance.
  • Signed energy: use signed sums and absolute diagnostic sums separately; no accidental abs(weight) in conservation.
  • DDMC diffusion: pure scattering gives <r²> = 6Dt with D = c/(3σ_s).
  • Constant field: preserve a constant solution on regular and distorted Voronoi meshes.
  • Reciprocity: local and cross-rank V_i λ_ij = V_j λ_ji.
  • Interface balance: static IMC-DDMC equilibrium current has no jump beyond tolerance.
  • Moving interface: moving-factor A/B test, no invalid factor substitution, threshold sweep at 3, 5, 10, 15, 30.
  • Frame handling: ordinary DDMC-to-DDMC leakage introduces no extra Lorentz shift; divergence redshift matches analytic homologous result.
  • Containment: every transport packet is in its declared cell after nudge/conversion; DDMC representative locations are explicitly exempt only while resident.
  • Zero-weight termination: no infinite scatter loop for zero initial/current weight.

15. Release, feature flags, and rollback strategy

15.1 Feature flags

  • withDDMC: after PR-11, selects the conservative path.
  • Temporary ddmcImplementation = Legacy|Conservative may be used only during A/B validation; remove it after signoff to avoid two permanent algorithms.
  • withCompton: remains rejected until C1–C7 are complete.
  • postProcess.enabled: remains rejected until observer/post-process core is complete.
  • Polarization stays compile-time gated and runtime validated.

15.2 Merge discipline

  • One high-risk semantic change per PR.
  • Every PR includes an “unchanged paths” section and before/after test table.
  • No PR removes the old behavior until the replacement has passed serial, Two-Sided, and at least one RDMA backend.
  • Keep source SHAs and copied mathematical formulas in code comments for auditability, but rewrite code into STORM abstractions.
  • Use deterministic microtests as merge blockers; run expensive statistical/multi-node suites nightly or before release.

15.3 Rollback points

  1. After packet-state plumbing, before physics.
  2. After static conservative DDMC, before moving interfaces.
  3. After moving interfaces, before momentum coupling.
  4. After forward core, before Compton.
  5. After observer core, before adaptive source/load balancing.

16. Definition of done

The integration is complete only when all statements below are true:

  1. Current ordinary STORM IMC examples and communication backends remain supported and pass feature-off regression tests.
  2. STORM’s generic Cartesian and Voronoi instantiations compile without RICH concrete types.
  3. Conservative DDMC uses two-sided resistance and validated mixed-band interface handling.
  4. DDMC packet representation state survives serialization, Two-Sided, MPI-RMA, IBV, OFI, population control, splitting, and reallocation.
  5. Static and moving IMC-DDMC interfaces pass detailed-balance and moving-interface validation.
  6. Zero-owned-cell MPI ranks do not hang and produce correct ghost metadata, packet transfer, and flux reduction.
  7. Energy and momentum ledgers close within declared tolerances in serial and distributed runs.
  8. DDMC and PGRW show an acceleration benefit on thick benchmarks without exceeding the error budget.
  9. Compton remains hard-incompatible with DDMC unless a future, separately reviewed derivation changes that rule.
  10. When Compton is enabled, signed source/residual tests and deterministic parity pass on all supported managers.
  11. Post-processing and polarization are optional modules and do not add mandatory dependencies to ordinary STORM builds.
  12. Application-specific TDE/CER workflows are either outside core or behind explicit reusable interfaces.
  13. Public documentation lists every supported/unsupported feature combination and the validated benchmark envelope.
