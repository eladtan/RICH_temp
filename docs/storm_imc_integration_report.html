Goal Interpreted

The user request was:

  • RICH should use the IMC implementation from STORM.
  • RICH should not keep a copied forward IMC implementation.
  • RICH should not keep copied helper classes that are part of the forward STORM IMC implementation.
  • The implementation should avoid splitting STORM IMC into many files for now.
  • The STORM IMC should template RICH-specific domain types such as cells, extensives, and EOS assumptions.

RICH Adapter Details

Parameter Alias

RICH no longer defines an independent parameter struct or global parameter alias. Call sites now use: 

STORM::RadiationIMCParameters<ENERGY_GROUPS_NUM>

This avoids unqualified-name ambiguity with STORM::RadiationIMCParameters and keeps the parameter type owned by STORM only.

Opacity Adapter

RICHRadiationOpacityAdapter wraps a std::shared_ptr<OpacityCalculator> and implements the STORM RadiationOpacityModel interface. This allows STORM IMC to call:

  • CalcPlanckOpacity(cell)
  • CalcAbsorptionOpacity(cell, frequency)
  • CalcScatteringOpacity(cell)
  • CalcScatteringOpacity(cell, frequency)
  • getRandomVelocity(cell, rng, dist)
  • getNewScatterVelocity(cell, oldVelocity, frequency, rng, dist)
  • ComptonIncludedInTransport()
  • reseed(seed)

The transport implementation stays in STORM; this adapter only bridges RICH's existing opacity API.

Traits Adapter

RICHRadiationIMCTraits supplies RICH-specific accessors for:

  • ComputationalCell3D::energyBoundaries
  • cell.tracers
  • ComputationalCell3D::tracerNames
  • cell.Eg[group]
  • conserved.Eg[group]

Position Sampler

RICHRadiationPositionSampler preserves RICH's previous behavior of sampling source packet positions through RandomPointInCell and nudging toward the mesh point. STORM's default sampler uses cell centers, but RICH supplies this sampler template argument.

Compatibility Class

The global RICH RadiationIMC class remains because many RICH callers store it as std::shared_ptr<MonteCarloRadiationPhysics3D> or dynamic-cast to RadiationIMC. A pure type alias would break those code paths. The adapter class keeps the public RICH shape while delegating implementation to STORM.

STORM IMC Current Feature Surface

The current STORM IMC port is intentionally conservative. It implements the gray IMC path and explicitly rejects features that have not yet been ported. This prevents RICH from silently running a removed copied implementation.

Important Consequence

Existing RICH executables or tests that set withRandomWalk = true, withMultigroupOpacity = true, withCompton = true, or withDDMC = true may still compile through the adapter, but they will fail at runtime during IMC construction until those features are ported into STORM.

This is deliberate. The code now refuses unsupported feature combinations instead of falling back to a stale RICH copy.

Bottom Line

RICH no longer contains a forward IMC implementation copy. The RICH RadiationIMC symbol is a compatibility adapter over STORM's templated RadiationIMC. The old RICH forward IMC source files and forward random-walk helper were deleted.

The current integration is a clean source-of-truth change, not full feature parity yet. STORM is now the place where every forward IMC feature must be implemented.
