Plan: Make STORM Own the Full IMC Module

Goal: replace STORM's reduced SimpleRadiationPhysics with a templated full-feature IMC module that preserves the behavior of the current RICH RadiationIMC implementation, while removing hard dependencies on ComputationalCell3D, RICH conserved/extensive state, and RICH EOS classes.

1. Executive Decision

Implement STORM::RadiationIMC as the only real IMC implementation. RICH's source/3D/radiation/RadiationIMC.hpp should become a thin compatibility wrapper or alias that instantiates the STORM template with Vector3D, Tessellation3D, ComputationalCell3D, Conserved3D or Extensives3D, EquationOfState, and OpacityCalculator.

1.1 What "full IMC" means here

The STORM module must include, at minimum, all features visible in the current RICH IMC files:

  • Ordinary gray IMC source generation, transport, Fleck factor, continuous absorption, effective scattering, and post-step material/radiation updates.
  • Hydrodynamic coupling through material energy and momentum feedback.
  • noHydroFeedback mode.
  • diffusionPressureGradient momentum coupling mode.
  • MMC moving-mesh particle advection and adiabatic radiation weight update.
  • Multigroup thermal emission, group finding, group energy tallies, group time averages, and group frequency sampling.
  • Adaptive source-cell packet allocation and learned source score controls.
  • Adaptive source-cell group biasing with bounded weight correction diagnostics.
  • Linearized Compton IMC data, matrix construction, modified Fleck factor, signed group sources, implicit in-place Compton events, parity diagnostics, signed tally checks, and group positivity projection.
  • Random-walk acceleration and multigroup PGRW acceleration.
  • DDMC acceleration from the parked RadiationIMC_DDMC.cpp source, including leak/census/upscatter events, PGRW collapsed DDMC, boundary exclusion, observer exclusion, counters, and debug info.
  • Observer and post-process hooks that are already present in parameter structs or parked DDMC code.
  • Optional polarization support under MONTECARLO_POLARIZATION.
  • RNG reseeding behavior for reproducible runs.
  • Compatibility with STORM serial and RDMA managers.

1.2 What should disappear from RICH

  • Do not keep two independent IMC implementations.
  • Do not keep SimpleRadiationPhysics as the primary radiation path.
  • Do not include RICH headers from inside source/monte.
  • Do not use ComputationalCell3D::energyBoundaries directly inside STORM.
  • Do not use UniversalError inside STORM. Use STORMError.
  • Do not use RICH_MPI inside STORM. Use STORM_WITH_MPI.

3. Known Blockers Before Coding

3.1 DDMC is currently inconsistent

RadiationIMC_DDMC.cpp references DDMCCellData, DDMCFaceLeak, withDDMC, ddmcCellData, postProcess_, useTransportVelocities_, and DDMC counters that are not declared in the current visible RadiationIMC.hpp. RICH CMake also removes RadiationIMC_DDMC.cpp from source collection.

The implementation plan must treat this as a restore-and-reconcile task, not as dead code. The request says "all features"; the parked DDMC file is part of that feature surface.

3.2 Signed Compton packets conflict with current comb population control

Both CombPopulationControl and StratifiedCombPopulationControl throw on negative packet weight. The Compton source path can emit signed packets. Full STORM IMC must either use NoPopulationControl when withCompton=true, or add a signed-safe comb algorithm that bins positive and negative packet weights separately.

3.3 Template code must be header-visible

The full IMC class will be templated on point, grid, cell, extensives, EOS, opacity, group count, and traits. Most implementation must live in headers or included .ipp files. Non-template helpers such as random-walk lookup table construction can live in .cpp.

4. Template Contract

The class must be generic, but it should not invent a complex runtime reflection layer. Use template parameters plus a small traits adapter. The implementation may assume the minimal fields exist, but every place where RICH used static globals, tracer names, or group boundaries should go through traits so standalone STORM cells can adapt cleanly.

4.5 Opacity model interface

The concrete opacity object does not need to be a template parameter. The revised recommendation is a typed STORM abstract interface: the interface is templated on PointT, GridT, CellT, and NumGroups because its methods mention those types, but RadiationIMC should store it as a std::shared_ptr<RadiationOpacityModel<...>>.

RICH should provide a tiny adapter that wraps its existing OpacityCalculator. Standalone STORM examples should implement the same interface directly. This keeps the main class template shorter without forcing RICH headers into STORM. 

template<typename PointT, typename GridT, typename CellT, std::size_t NumGroups>
class RadiationOpacityModel {
public:
    using MCParticle = Particle<PointT, GridT>;
    virtual ~RadiationOpacityModel() = default;

    virtual double CalcPlanckOpacity(CellT const& cell) const = 0;
    virtual double CalcScatteringOpacity(CellT const& cell) const { return 0.0; }
    virtual double CalcAbsorptionOpacity(CellT const& cell, double energy) const = 0;
    virtual double CalcScatteringOpacity(CellT const& cell, double energy) const
    {
        (void)energy;
        return CalcScatteringOpacity(cell);
    }
    virtual PointT getRandomVelocity(CellT const& cell) const = 0;
    virtual PointT getNewScatterVelocity(CellT const& cell, MCParticle& particle) const
    {
        (void)particle;
        return getRandomVelocity(cell);
    }
    virtual bool ComptonIncludedInTransport() const { return false; }
    virtual void reseed(uint64_t seed) { (void)seed; }
};

Group lookup should be implemented by RadiationIMC from its own energyBoundaries_. Do not require opacity models to own group boundaries. A RICH adapter may still forward to OpacityCalculator::findGroup only as an optimization, but the STORM IMC result must not depend on that.

The RICH-side adapter should look like this in shape:

class RichOpacityAdapter final
    : public STORM::RadiationOpacityModel<Vector3D, Tessellation3D,
                                          ComputationalCell3D,
                                          ENERGY_GROUPS_NUM>
{
public:
    using MCParticle = STORM::Particle<Vector3D, Tessellation3D>;

    explicit RichOpacityAdapter(std::shared_ptr<OpacityCalculator> opacity)
        : opacity_(std::move(opacity)) {}

    double CalcPlanckOpacity(ComputationalCell3D const& cell) const override
    { return opacity_->CalcPlanckOpacity(cell); }

    double CalcScatteringOpacity(ComputationalCell3D const& cell) const override
    { return opacity_->CalcScatteringOpacity(cell); }

    double CalcAbsorptionOpacity(ComputationalCell3D const& cell, double energy) const override
    { return opacity_->CalcAbsorptionOpacity(cell, energy); }

    double CalcScatteringOpacity(ComputationalCell3D const& cell, double energy) const override
    { return opacity_->CalcScatteringOpacity(cell, energy); }

    Vector3D getRandomVelocity(ComputationalCell3D const& cell) const override
    { return opacity_->getRandomVelocity(cell); }

    Vector3D getNewScatterVelocity(ComputationalCell3D const& cell, MCParticle& particle) const override
    { return opacity_->getNewScatterVelocity(cell, particle); }

    bool ComptonIncludedInTransport() const override
    { return opacity_->ComptonIncludedInTransport(); }

    void reseed(uint64_t seed) override
    { opacity_->rng_.seed(seed); }

private:
    std::shared_ptr<OpacityCalculator> opacity_;
};

4.7 TraitsT required responsibilities

template<typename PointT, typename CellT, typename ExtensivesT, std::size_t NumGroups>
struct DirectRadiationIMCTraits {
    using GroupArray = std::array<double, NumGroups>;

    std::array<double, NumGroups + 1> energyBoundaries(CellT const& sampleCell) const;
    double groupEnergyPerMass(CellT const& cell, std::size_t g) const;
    double& groupEnergyPerMass(CellT& cell, std::size_t g) const;
    double& extensiveGroupEnergy(ExtensivesT& ext, std::size_t g) const;
    double extensiveGroupEnergy(ExtensivesT const& ext, std::size_t g) const;
    auto const& tracers(CellT const& cell) const;
    auto const& tracerNames(CellT const& cell) const;
};

The default direct traits may access cell.Eg[g], ext.Eg[g], cell.tracers, and a static CellT::energyBoundaries. The RICH wrapper should provide an explicit RichRadiationIMCTraits so future RICH field renames are localized.

Keep this traits object narrow. It is not a second opacity interface, not an EOS wrapper, and not a substitute for the minimal fields listed above. It exists only for data that was previously RICH-static or easy to spell differently across host codes.

4.8 PositionSamplerT required responsibilities

PositionSamplerT is used only to create the initial location of newly emitted internal IMC particles. It should not own physics, opacities, EOS state, or source weights. 

template<typename PointT, typename GridT>
struct CellCenterPositionSampler {
    PointT operator()(GridT const& grid,
                      std::size_t cellIndex,
                      std::mt19937_64& rng,
                      std::uniform_real_distribution<double>& dist) const;
};
Sampler input Used for Required behavior
grid Access cell center, faces, or host-specific random-in-cell helper. Do not store a dangling grid reference inside the sampler unless it is intentionally copied or reference-wrapped.
cellIndex Select which cell receives the source packet. Returned point must be inside that cell or must be nudged so grid.IsPointInCell(point, cellIndex) succeeds.
rng and dist Generate reproducible random positions. Use the IMC RNG passed in. Do not create static RNG state in the sampler.

The default STORM sampler may return the mesh point nudged inside the cell. The RICH wrapper should pass a sampler that calls RICH's RandomPointInCell, because that preserves the current RadiationIMC::generateSingleParticle behavior without making STORM include RICH geometry helpers.

5.1 Header inclusion rule

source/monte may include STORM headers, C++ standard headers, Boost headers already allowed by STORM, and optional STORM-owned Compton headers. It must not include newtonian/..., 3D/radiation/..., misc/universal_error.hpp, or Radiation/CMMC/....

5.2 CMake rule

Because the full IMC class is templated, keep the first implementation in RadiationIMC.hpp and make it header-visible. Only non-template files such as RandomWalk.cpp and optional Compton matrix files should be added to STORM_SOURCES. Feature-specific header splitting is a later cleanup task, not part of the initial migration.

Option Default Meaning Implementation notes
newPhotonsPerCell 0 in the proposed STORM struct; required to be positive for normal source generation. Baseline number of newly emitted thermal source packets per local cell per IMC step. Validate > 0 in the constructor unless the caller explicitly disables all internal source generation. Ordinary source allocation uses this as the minimum and caps proportional allocation at 20 * newPhotonsPerCell. Compton source generation uses at least this many packets per active source cell.
withHydro false Enable radiation-material momentum coupling and mixed-frame velocity corrections. When true and MMC=false, compute Doppler factors, Lorentz-transform emitted/scattered packets, apply gamma factors in source terms, and update material momentum unless diffusionPressureGradient or noHydroFeedback prevents direct momentum feedback.
diffusionPressureGradient false Use the post-step radiation pressure-gradient approximation for momentum feedback instead of per-event packet momentum exchange. Only meaningful with withHydro=true. Current RICH code uses a 1D x-gradient estimate; the STORM port must preserve behavior first and document that limitation before generalizing it.
MMC false Moving-mesh Monte Carlo mode. Disables mixed-frame Doppler/Lorentz behavior in transport and enables adjustExistingParticles, which advects packet locations with cell velocity and applies the -w div(v) dt / 3 radiation work update.
withMultigroupOpacity false Enable energy/frequency groups and group-dependent absorption opacity. Construct the generic MultigroupOpacity helper, initialize group boundaries/centers, sample thermal emission frequencies, find particle groups during transport, and tally Eg. Required when withCompton=true.
withRandomWalk false Enable random-walk acceleration in optically thick cells. Construct and precompute random-walk cell eligibility. Current Compton implementation is guarded against random walk; preserve the error for withCompton && withRandomWalk until a mathematically equivalent combined scheme is implemented.
rwMinCellOpticalDepth 25.0 Minimum cell optical depth for a cell to be eligible for random-walk acceleration. Use sigmaT * meanChordLength. In multigroup PGRW, compute the cutoff group and collapsed diffusion coefficients before setting eligibility.
rwMinParticleOpticalDepth 5.0 Minimum particle optical depth to the nearest face before actually taking a random-walk step. Use Ro * sigmaT, where Ro is the minimum signed distance to the current cell faces from the packet location.
withDDMC false Enable discrete diffusion Monte Carlo acceleration in optically thick cells. The current DDMC implementation is parked in RadiationIMC_DDMC.cpp. The STORM port must restore declarations, wire precomputeDDMCData and tryDDMCStep, and expose DDMC counters. If not implemented yet, constructor must throw when this is true.
ddmcMinCellOpticalDepth 15.0 Minimum cell optical depth for DDMC cell eligibility. Use sigmaT * meanChordLength for gray DDMC. In PGRW-collapsed multigroup DDMC, use group-resolved opacities to choose a diffusive group cutoff.
ddmcMinParticleOpticalDepth 5.0 Minimum particle optical depth to active DDMC leak faces. Packets too close to a leak face must fall back to analog IMC and increment DDMC fallback counters.
ddmcUseMultigroupPGRW false Use collapsed PGRW-style multigroup DDMC for low-energy diffusive groups. Only meaningful with withDDMC=true and withMultigroupOpacity=true. DDMC must reject packets whose comoving frequency is above the diffusive cutoff.
noHydroFeedback false Transport radiation without changing material energy, total energy, or momentum. All source withdrawals, absorption deposits, Compton exchanges, removal deposits, and momentum updates must be skipped when true. Radiation tallies still update.
withEgTimeAvg false Accumulate time-averaged group radiation energy density during transport. Only meaningful with multigroup opacity. Accumulate signed integrated packet weight per group during steps and normalize in postStep by fullDt * volume.
withCompton false Enable the linearized Compton IMC scheme. Requires multigroup opacity. Builds Compton matrices, modified Fleck factors, signed group sources, implicit in-place event kernels, diagnostics, and signed tally checks.
comptonUseInduced true Include induced Compton terms by using the old radiation occupation number in matrix construction. When false, build matrices with zero occupation numbers. When true but the modified Fleck denominator is unsafe, comptonAllowNZeroFallback may rebuild with zero occupation.
comptonAllowNZeroFallback true Allow fallback to occupation-number-zero Compton matrices when induced terms produce an unsafe denominator or strongly negative Upsilon. Increment comptonNZeroFallbackCount. If fallback is disabled and the denominator is nonpositive, throw.
comptonDebugParityCheck false Run per-cell debug checks proving the in-place stochastic kernels reconstruct the deterministic Compton operator. Call validateComptonParity after building kernels. This is expensive and should remain opt-in.
comptonCheckSignedTallies false After post-step tallying, verify signed packet sums did not create unacceptably negative radiation or group energy. Use comptonSignedTallyTolerance * max(absWeightTally, 1) for both total and per-group checks.
comptonDiagnostics false Print or expose Compton diagnostic reductions. Reduce source/continuous/event/removal material exchange, min/max group energies, projected radiation energy, min/max Fleck/Gamma/Upsilon, fallback counts, opacity-limited groups, and projected negative groups.
comptonAngleDependent true API flag for angle-dependent Compton treatment. The visible current implementation does not use this flag. The STORM port must either wire it into the Compton matrix/event model or explicitly document it as currently ignored for compatibility. Do not let it imply verified behavior if it remains a no-op.
comptonSignedTallyTolerance 1e-10 Relative tolerance for signed Compton tally negativity checks. Used only when comptonCheckSignedTallies=true. Keep default equal to current RICH parameter.
comptonMatrixSamples 200000 Monte Carlo sample count used by the Compton matrix generator. Forward to ComptonMatrixMC. Expose in parameter logging so runs are reproducible.
energyBoundaries All zeros until provided. Optional explicit group boundary array. If energyBoundariesProvided=true, validate strict monotonicity and use this array. Otherwise ask TraitsT::energyBoundaries for host-provided boundaries.
energyBoundariesProvided false Select whether energyBoundaries overrides traits-provided boundaries. Useful for standalone STORM examples that do not want static cell globals.
postProcess.enabled false Enable post-process observer behavior used by the parked DDMC path. DDMC uses this to exclude cells near the observer surface and to use tighter low-weight cutoff/observer energy accounting.
postProcess.sourceDt 0.0 Source time interval for post-process observer/statistical output. Retain in STORM parameters even if only the RICH observer wrapper consumes it initially.
postProcess.transportTime 0.0 Post-process transport time horizon. Retain for API parity; if no STORM code consumes it in the first port, document as stored-only.
postProcess.useCellVelocities true Use cell velocities during post-process/mixed-frame transport. Maps to the parked DDMC useTransportVelocities_ behavior. Do not leave useTransportVelocities_ undeclared.
postProcess.polarization.enabled false Enable polarization state propagation and observer Stokes tallies where supported. Only compile behavior under MONTECARLO_POLARIZATION. If requested without polarization build support, throw or clearly disable with a diagnostic.
postProcess.polarization.manualScatteringsAfterAcceleration 0 Number of synthetic/manual scatterings applied after accelerated DDMC history. Forward to IMCPolarization::ApplyAcceleratedPolarizationHistory in the DDMC port.
postProcess.polarization.depolarizationScatterings 0.0 Effective scattering count scale for depolarization in accelerated transport. Forward to polarization closure. Values above zero should reduce retained polarization through the selected closure model.
postProcess.polarization.acceleratedClosure Empty string. Name of the accelerated-transport polarization closure. Define accepted strings in STORM, for example synthetic, depolarize, or none. Reject unknown non-empty strings rather than silently using a default.

9. Algorithmic Details to Preserve

9.1 Energy conventions

  • Cell Erad and Eg are per-mass in RICH.
  • Extensive Erad and Eg are total energy in the cell.
  • Particle weight is packet energy. It can be negative for signed Compton packets.
  • Continuous absorption deposits oldWeight * (1 - exp(-rate dt)) with signed semantics.
  • Material source generation subtracts emitted energy from extensive internal energy unless noHydroFeedback.

9.2 Fleck factor

gamma = withHydro && !MMC ? 1 / sqrt(1 - dot(v, v) / c^2) : 1;
cv = eos->dT2cv(cell.density, cell.temperature, traits.tracers(cell), traits.tracerNames(cell));
f = 1 / (1 + 4 * arad * T^3 * planckOpacity * c * fullDt * gamma / cv);

For Compton, replace planckOpacity with Gamma and include beta, Upsilon, and the n=0 fallback exactly as current code does.

9.3 Event selection in ordinary IMC

  1. Compute face-intersection time.
  2. Compute event opacity.
  3. Sample event distance.
  4. Convert event distance to event time by dividing by particle speed.
  5. Pick minimum of face, event, and census time.
  6. Move particle by velocity * dt.
  7. Apply continuous absorption and tallies before event-specific action.
  8. For face event, return CELL_MOVE and next cell.
  9. For event, choose elastic scatter, effective absorption scatter, or implicit Compton event.
  10. For census, return DONE.

9.4 Signed packet rules

  • Always compare low-weight cutoff using abs(weight) and initialWeight = abs(initial weight).
  • Radiation energy tallies use signed weight.
  • Diagnostics that measure packet magnitude use abs(weight).
  • Population control must not throw on negative weights when Compton is enabled.
  • MPI serialization already carries weight and initialWeight; verify signed round trips explicitly.

9.5 Signed-safe population control

Recommended implementation:

  1. Create SignedCombPopulationControl in STORM.
  2. Bin particles by cell, sign, and optionally group.
  3. For each bin, run the existing comb algorithm on absolute weights.
  4. Restore the bin sign on output weights.
  5. Set initialWeight = abs(weight).
  6. Preserve cell, group, frequency, location, velocity, polarization fields, cellID, and sourceCellID.
  7. Never combine positive and negative packets in the comb itself. Cancellation can be a later variance-control feature.

9.6 Random point in cell

The old RICH code uses RandomPointInCell. STORM should not include that helper. Add a PositionSamplerT policy:

  • Default sampler: return grid.GetMeshPoint(cellIndex) nudged inside the cell. This preserves old SimpleRadiation behavior.
  • RICH sampler: call RICH's RandomPointInCell from the wrapper if exact old RICH sampling is required.
  • Future STORM sampler: implement convex-cell rejection or tetrahedral sampling using grid faces, but do not block this migration on it.

9.7 DDMC ordering

Recommended order inside step: try DDMC, then try random walk, then ordinary analog IMC. This keeps DDMC as the high-optical-depth diffusion accelerator and RW/PGRW as fallback. If physics owners prefer current RW priority, change the order in one place and add a comment.

9.8 Error translation

Every old UniversalError must become STORMError. Preserve all diagnostic entries.

STORMError eo("Invalid factor fleck in STORM::RadiationIMC::preStep");
eo.addEntry("Factor fleck", factorFleck[i]);
eo.addEntry("Planck opacity", planckOpacities[i]);
eo.addEntry("Temperature", cells[i].temperature);
eo.addEntry("Density", cells[i].density);
eo.addEntry("Gamma", gamma);
eo.addEntry("cv", cv);
eo.addEntry("Full dt", fullDt);
throw eo;

11. Anti-Footgun Rules for the Implementer

  1. Do not copy ComputationalCell3D includes into STORM.
  2. Do not copy Conserved3D includes into STORM.
  3. Do not copy EquationOfState includes into STORM.
  4. Do not add #ifdef RICH_MPI to STORM files.
  5. Do not leave ENERGY_GROUPS_NUM in STORM IMC implementation.
  6. Do not access ComputationalCell3D::energyBoundaries from STORM.
  7. Do not use UniversalError from STORM.
  8. Do not make Compton depend on random walk until the math is implemented. Keep the guard.
  9. Do not use existing comb population control for signed Compton packets.
  10. Do not assume packet weights are positive in post-step tallies.
  11. Do not normalize time-average tallies twice.
  12. Do not update material energy when noHydroFeedback is true.
  13. Do not update hydro momentum when diffusionPressureGradient is true except in the post-step pressure-gradient path.
  14. Do not forget gamma factors in moving hydro source terms.
  15. Do not sample multigroup frequencies outside boundaries; clamp after Doppler/Lorentz transforms.
  16. Do not reset initialWeight to a signed value. Use absolute magnitude.
  17. Do not silently drop parked DDMC. Either port it or explicitly disable withDDMC with a runtime error until ported.
  18. Do not keep old RICH RadiationIMC.cpp as active physics after STORM version is live.
  19. Do not let the RICH wrapper accumulate business logic. It should instantiate and forward only.
  20. Do not finish without testing STORM standalone and RICH embedding.
