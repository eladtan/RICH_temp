STORM IMC — Missing Features Report

Generated: July 1, 2026  |  Branch: submodules_integration  |  Reference: origin/ablation

Summary: STORM's templated RadiationIMC module is functionally complete for gray and multigroup IMC with random walk and DDMC. Three major features from the old RICH ablation branch have not yet been ported: Compton scattering, Spherical Observer (peel-off), and Adaptive source allocation.

1. Implicit Compton Scattering HIGH COMPLEXITY

What it does

The old IMC implements a fully implicit Compton scattering scheme that couples energy groups through scattering matrices. When a photon packet undergoes a Compton event, it can change frequency group according to a precomputed redistribution kernel, conserving energy between the radiation field and the material.

Integration points in transport loop

  • step(): Modified absorption opacity lookup when Compton active
  • step(): Additional event type (implicit Compton) alongside absorption/scattering
  • step(): Weight evolution includes implicitDiagonalCorrection
  • step(): Re-emission uses Compton source CDF instead of Planck when active
  • preStep(): Calls precomputeComptonData and generateComptonParticles
  • postStep(): Compton diagnostics printed if enabled

External dependency

ComptonMatrixMC — a separate class (not shown) that computes Compton scattering kernels from the Klein-Nishina cross section. Likely in source/Radiation/.

Estimated porting effort

~600 lines of physics code + ~40 lines of data structure definitions + integration hooks in step(). Requires careful handling of the GroupMatrix and GroupCdfMatrix types (2D arrays of size NumGroups × NumGroups). The ComptonMatrixMC dependency needs to be made STORM-compatible or wrapped in an adapter.

2. Spherical Observer (Peel-Off) MEDIUM COMPLEXITY

What it does

A SphericalObserver is placed at a given radius from the origin. Every time a photon packet undergoes an event (emission, scattering, or absorption/re-emission), a deterministic "peel-off" contribution is computed toward the observer sphere. This builds up a synthetic spectrum/light curve without requiring photons to actually reach the observer.

Integration points

  • RadiationIMC holds shared_ptr<SphericalObserver>, set via setObserver()
  • During step(): after each event, compute peel-off toward observer
  • postStep(): MPI reduce observer tallies, output if requested
  • Provides cell-level escape scores used by adaptive source allocation

Estimated porting effort

The SphericalObserver class itself is ~500 lines and mostly self-contained. Integration into STORM requires templating the observer interface on PointT and adding peel-off hooks to the transport loop. The geometry (ray-sphere intersection) is straightforward. The main complexity is the MPI reduction and the connection to adaptive source scoring.

3. Adaptive Source Allocation MEDIUM COMPLEXITY

What it does

Biases photon emission towards cells that contribute more to the observable signal (determined by previous-generation escape statistics from the observer). This is a variance reduction technique: cells with higher "importance scores" receive more photon packets, improving signal-to-noise without increasing total photon budget.

Two levels of adaptation

A. Cell-level adaptive budget

ParameterDescription
adaptiveSourceStrength_Blending factor [0,1]: 0 = uniform, 1 = fully importance-driven
adaptiveSourceMaxFactor_Maximum multiplier on per-cell photon count (e.g. 10×)
adaptiveSourceLearnedReserveFrac_Fraction of budget reserved for learned-importance cells
adaptiveSourceLearnedMinFactor_Minimum multiplier for cells with any learned score
adaptiveSourceObserverBudgetMultiplier_Overall budget multiplier when observer is active
adaptiveSourceScores_unordered_map<cellID, score> from previous generation

B. Group-level adaptive frequency sampling

ParameterDescription
adaptiveGroupStrength_Blending factor for group PDF biasing
adaptiveGroupPdfFloor_Minimum probability per group (prevents zero sampling)
adaptiveGroupMaxBias_Maximum ratio of biased/physical PDF
adaptiveGroupMaxWeightCorrection_Maximum weight correction factor
adaptiveSourceCellGroupScores_unordered_map<cellID, GroupArray> per-group scores

Algorithm sketch (cell-level)

// In generateParticles():
for each cell i:
    baseBudget = proportionalShare(energy_i, totalEnergy, totalParticles)
    if adaptiveEnabled and cell has score:
        factor = lerp(1.0, score * normalization, adaptiveStrength)
        factor = clamp(factor, learnedMinFactor, maxFactor)
        nPhotons = baseBudget * factor
    weight_per_photon = energy_i / nPhotons   // maintains energy conservation

Algorithm sketch (group-level)

// In generateParticles(), per-photon frequency sampling:
physicalPdf[g] = planckFraction[g]   // or Compton source fraction
if adaptiveGroupEnabled and cell has group scores:
    learnedPdf = normalize(groupScores[cellID])
    samplingPdf = (1-strength)*physicalPdf + strength*learnedPdf
    samplingPdf = clamp(samplingPdf, floor, maxBias*physicalPdf)
    sample group from samplingPdf
    weightCorrection = physicalPdf[sampledGroup] / samplingPdf[sampledGroup]
    particle.weight *= weightCorrection

Integration points

  • setAdaptiveSourceCellScores() / clearAdaptiveSourceCellScores()
  • setAdaptiveSourceCellGroupScores() / clearAdaptiveSourceCellGroupScores()
  • Called externally between generations (typically from the run's main loop)
  • Scores come from SphericalObserver's per-cell escape statistics
  • Modifies generateParticles(): per-cell photon budget and frequency PDF

Estimated porting effort

~200 lines in generateParticles for the biasing logic, plus ~50 lines for the set/clear interface. Algorithmically straightforward (weighted sampling with clamping). Depends on the observer providing cell-escape statistics, so should be ported after the observer.
