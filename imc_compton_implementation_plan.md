# Implementation plan: add the linearized Compton IMC scheme to `RadiationIMC`

## 0. Purpose of this document

This document is a coding plan for modifying the current `RadiationIMC.cpp` implementation so it can include the same multigroup Compton linearization used by the deterministic multigroup diffusion code, but in an IMC transport calculation.

The key implementation problem is that the Compton-modified implicit material response produces a signed effective-scattering matrix. Ordinary IMC can only sample nonnegative collision probabilities. The plan below keeps the existing IMC structure for the nonnegative part, adds physical or residual Compton transport, and represents the signed negative part with signed residual packets, also called anti-packets. All Compton coefficients are frozen at the beginning of the time step. No nonlinear iterations, source iterations, or post-transport fixed-point iterations are added.

This document is deliberately explicit. It is written so that a simple coding agent can implement the change by following the phases and checklists in order.

## 2. Mathematical target implemented by the code

Everything in this section is cell-local. The cell index is omitted unless needed.

Use group indices:

- `h` = source group of an existing packet or existing radiation energy.
- `g` = target group of a newly emitted, scattered, or residual packet.
- `q` = summed group.

Old-state quantities at time `n`:

- `E_h^n`: old radiation energy density in group `h`. In the current hydro state this is usually `cell.Eg[h] * cell.density`.
- `T^n`: old material temperature.
- `U_m^n = a_r (T^n)^4`: radiation-equivalent material energy variable used by the Fleck linearization.
- `kappa_g`: absorption opacity in group `g`.
- `b_g`: Planck fraction in group `g`.
- `kappa_P = sum_g kappa_g b_g`: Planck mean absorption opacity.
- `S_{h->g}`: direct Compton radiation-energy operator evaluated at `T^n`.
- `dS_{h->g}/dU_m`: derivative of the Compton operator with respect to the material energy variable, evaluated at `T^n`.

The Compton contractions used by the implicit material response are

```math
D_g = \sum_h \left(\frac{\partial S_{h\to g}}{\partial U_m}\right)^n E_h^n,
```

```math
\Upsilon = \sum_g D_g
          = \sum_h \sum_g \left(\frac{\partial S_{h\to g}}{\partial U_m}\right)^n E_h^n,
```

```math
M_g = \kappa_g b_g + D_g,
```

```math
\Lambda_h = \kappa_h - \sum_q S_{h\to q}.
```

The Compton-modified Fleck denominator is

```math
\Gamma = \kappa_P + \Upsilon,
```

```math
f = \frac{1}{1 + \beta c \Delta t\,\Gamma},
```

where `beta` must be computed with the same convention already used by the IMC Fleck factor. In the current `RadiationIMC.cpp` this means the expression at line 479 generalizes from

```cpp
1.0 / (1.0 + 4 * arad * T^3 * kappaP * c * dt * gamma / cv)
```

to

```cpp
1.0 / (1.0 + 4 * arad * T^3 * Gamma * c * dt * gamma / cv)
```

when Compton is enabled.

The material-mediated implicit kernel is

```math
K^{mat}_{h\to g} = \beta c\Delta t\, f\, M_g\,\Lambda_h.
```

This kernel is signed. It is the main source of the negative effective-scattering problem.

The current IMC code already represents a nonnegative base absorption effective scattering. With the Compton-modified Fleck factor this base kernel is

```math
H^{base}_{h\to g} = (1-f)\,\kappa_h\,q_g,
```

where `q_g` must be exactly the group probability used by the ordinary effective absorption re-emission event. For correctness use

```math
q_g = \frac{\kappa_g b_g}{\kappa_P}
```

when `kappa_P > 0`; otherwise set all `q_g = 0`.

The residual kernel that is not already represented by the current IMC effective scattering event is

```math
R_{h\to g} = K^{mat}_{h\to g} - H^{base}_{h\to g} + S^{res}_{h\to g}.
```

Here `Sres` is the part of direct Compton not represented by an explicit physical Compton collision.

Recommended production implementation:

```math
S^{res}_{h\to g} = S_{h\to g} - S^{analog}_{h\to g},
```

where `Sanalog` is the expectation of the explicit positive physical Compton collision sampler.

Simplest exact implementation:

```math
S^{analog}_{h\to g}=0,
\qquad
S^{res}_{h\to g}=S_{h\to g}.
```

The simplest implementation preserves the linearized multigroup equation exactly in expectation, but it represents direct Compton partly with signed residual packets instead of physical group-changing collisions. Implement the simplest version first if time is limited, then add physical analog Compton as an optimization and physics-improving step.

Split the residual kernel into nonnegative parts:

```math
R^+_{h\to g}=\max(R_{h\to g},0),
\qquad
R^-_{h\to g}=\max(-R_{h\to g},0).
```

The residual contribution is sampled by creating child packets along each track segment:

```math
R_{h\to g}=R^+_{h\to g}-R^-_{h\to g}.
```

A positive residual child has the same sign as its parent. A negative residual child has the opposite sign.

## 3. Source term to emit at the beginning of the step

The current code generates the standard IMC material source in `generateParticles`. With Compton enabled, replace that source path by a group-specific signed source.

The base source that ordinary IMC would emit is

```math
B^{base}_g = V\,c\Delta t\, f\,\kappa_g b_g\,U_m^n.
```

The deterministic Compton source correction from `get_implicit_compton_contribution_to_b` is

```math
B^{corr}_g
= V\,c\Delta t\,\kappa_P U_m^n
  \left[
    \frac{\kappa_g b_g}{\kappa_P}
       \left(1-(1+\beta c\Delta t\,\kappa_P)f\right)
    - \beta c\Delta t\, f\,D_g
  \right].
```

The total source emitted by the Compton-enabled IMC code should be

```math
B^{total}_g = B^{base}_g + B^{corr}_g.
```

Equivalently, after simplification,

```math
B^{total}_g
= V\,c\Delta t\,U_m^n
  \left[
      \kappa_g b_g\left(1-\beta c\Delta t\,\kappa_P f\right)
      - \kappa_P\,\beta c\Delta t\,f\,D_g
  \right].
```

Use the unsimplified `Bbase + Bcorr` form in code because it is easier to compare to the deterministic implementation.

Important: when Compton is enabled, do not also call the old scalar thermal-source logic from line 367. Either generate `Btotal_g` directly, or keep the old source and generate only `Bcorr_g`. The recommended implementation is to generate `Btotal_g` directly in a new function `generateComptonParticles(fullDt)`.

Split the source by sign:

```math
B^{total,+}_g = \max(B^{total}_g,0),
\qquad
B^{total,-}_g = \max(-B^{total}_g,0).
```

Emit positive source packets for `Btotal,+`. Emit anti-packets or negative signed packets for `Btotal,-`. Material energy is updated by the negative of the signed emitted radiation energy. Therefore a negative radiation source packet increases the material energy.

## 4. High-level code architecture

Add Compton support in small phases. Keep `withCompton=false` behavior as close to bitwise identical as possible.

### Phase A: signed packet support with no Compton

Goal: allow the transport code to safely carry negative packet weights, but do not generate any negative packets yet.

Required changes:

1. Keep using `particle.weight` as the signed packet energy.
2. Treat `particle.initialWeight` as an absolute reference weight.
3. Replace all packet-removal checks based on raw `weight` by checks based on `std::abs(weight)`.
4. Make all material and momentum updates use the signed packet weight. Most already do this automatically.
5. Make all estimators and final tallies signed. Most already do this automatically.
6. Add diagnostics for negative radiation energy after tallying, but do not silently clip unless the negative value is a tiny roundoff tolerance and the code already has an explicit conservation correction.

Specific current-code edits:

- In `step`, replace line 146 logic:

```cpp
if(particle.weight < particle.initialWeight * 1e-3)
```

with

```cpp
if(std::abs(particle.weight) < particle.initialWeight * 1e-3)
```

and ensure `particle.initialWeight > 0` for every particle.

- In `generateParticles`, line 447:

```cpp
particle.initialWeight = std::abs(particle.weight);
```

- In `generateInitialParticles`, line 557:

```cpp
p.initialWeight = std::abs(weightPerPhoton);
```

- For any new residual child packet:

```cpp
child.initialWeight = std::abs(child.weight);
```

- In any future roulette function, roulette on `std::abs(weight)`, not on `weight`.

Do not add a separate sign field unless the rest of the Monte Carlo framework forbids negative `weight`. If a separate sign field is required, define the signed energy as `signedWeight = sign * weightAbs`, and replace every energy/momentum/tally expression by `signedWeight`.

#### C.2 Planck group fractions

```cpp
std::array<double, ENERGY_GROUPS_NUM> ComputePlanckFractions(const ComputationalCell3D& cell)
{
    std::array<double, ENERGY_GROUPS_NUM> b{};
    const double kT = units::k_boltz * cell.temperature;
    double sum = 0.0;
    for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
    {
        const double x0 = ComputationalCell3D::energyBoundaries[g] / kT;
        const double x1 = ComputationalCell3D::energyBoundaries[g + 1] / kT;
        b[g] = planck_integral::planck_integral(x0, x1);
        sum += b[g];
    }
    // Do not renormalize silently. Log if sum is far from 1 because that means the group grid misses part of the Planck spectrum.
    return b;
}
```

Include the same `planck_integral` header used by `MultigroupDiffusion.cpp`.

#### C.3 Safe CDF builder

```cpp
template <size_t N>
std::array<double, N + 1> BuildCdf(const std::array<double, N>& weights)
{
    std::array<double, N + 1> cdf{};
    cdf[0] = 0.0;
    double sum = 0.0;
    for(size_t i = 0; i < N; ++i)
    {
        sum += std::max(0.0, weights[i]);
        cdf[i + 1] = sum;
    }
    if(sum > 0.0)
    {
        for(size_t i = 1; i <= N; ++i)
            cdf[i] /= sum;
        cdf[N] = 1.0;
    }
    return cdf;
}
```

Add a group sampler:

```cpp
template <size_t N>
size_t SampleFromCdf(const std::array<double, N + 1>& cdf, double xi)
{
    if(cdf[N] <= 0.0)
        return std::numeric_limits<size_t>::max();
    xi = std::clamp(xi, 0.0, std::nextafter(1.0, 0.0));
    auto it = std::upper_bound(cdf.begin(), cdf.end(), xi);
    size_t g = static_cast<size_t>(std::distance(cdf.begin(), it)) - 1;
    return std::min(g, N - 1);
}
```

#### C.5 Integrated signed weight over a path segment

Residual source packets should be generated from a track-length estimator. Because the existing code applies continuous absorption over the segment, use the attenuation-integrated packet weight, not only the end-of-segment weight.

Add:

```cpp
double IntegratedWeightOverDt(double signedWeightAtStart, double alpha, double dt)
{
    // alpha is the continuous absorption rate in 1/time.
    // For the current code alpha = factorFleck[cell] * absorptionOpacity * units::clight.
    const double x = alpha * dt;
    if(std::abs(x) < 1e-10)
    {
        return signedWeightAtStart * dt * (1.0 - 0.5 * x + x * x / 6.0);
    }
    return signedWeightAtStart * (-std::expm1(-x)) / alpha;
}
```

This returns `integral_0^dt W(t) dt`. The residual source energy for an opacity-like kernel `R` is then

```cpp
sourceEnergy = units::clight * rateFrameFactor * IntegratedWeightOverDt(...) * Rrow;
```

For non-moving material, `rateFrameFactor = 1`. For the current hydro/Doppler convention, use the same Doppler factor that is used to convert opacity to event distance. A conservative first implementation can set

```cpp
double rateFrameFactor = (withHydro && !MMC) ? dopplerShift : 1.0;
```

and then verify against nonrelativistic tests first.

#### C.6 Residual source birth time on a segment

For exact time placement, sample the birth time with probability proportional to the attenuated parent weight along the segment.

```cpp
double SampleBirthTimeOnSegment(double alpha, double dt, double xi)
{
    xi = std::clamp(xi, 0.0, std::nextafter(1.0, 0.0));
    const double x = alpha * dt;
    if(std::abs(x) < 1e-10)
        return dt * xi;
    // CDF(t) = (1 - exp(-alpha t)) / (1 - exp(-alpha dt))
    const double denom = -std::expm1(-x);
    return -std::log1p(-xi * denom) / alpha;
}
```

If this is too much for the first coding pass, place residual children at the end of the segment. That is less accurate in time but still often first-order consistent. The recommended production version should sample the birth time.

#### C.7 Signed child packet creation

Add a helper:

```cpp
void RadiationIMC::BankSignedChildPacket(
    size_t cellIndex,
    const ComputationalCell3D& cell,
    const Vector3D& location,
    const Vector3D& parentVelocity,
    double timeLeft,
    size_t targetGroup,
    double signedEnergy,
    std::vector<Particle>& particlesToAdd)
{
    if(signedEnergy == 0.0)
        return;

    // Optional unbiased roulette for very small children.
    const double absE = std::abs(signedEnergy);
    double floor = signedPacketRouletteFloor;
    if(floor <= 0.0)
    {
        // A reasonable default: a fraction of the source packet scale.
        // Keep this simple initially; set to 0 to disable roulette until tests pass.
        floor = 0.0;
    }
    if(floor > 0.0 && absE < floor)
    {
        const double p = absE / floor;
        if(this->dist(this->re) > p)
            return;
        signedEnergy = std::copysign(floor, signedEnergy);
    }

    Particle child = this->generateSingleParticle(cellIndex, cell);
    child.location = location;
    child.cellIndex = cellIndex;
    child.cellID = cell.ID;
    child.timeLeft = std::max(0.0, timeLeft);
    child.frequency = FrequencyForGroup(targetGroup);
    child.weight = signedEnergy;
    child.initialWeight = std::abs(signedEnergy);

    // Material-mediated residual emission is isotropic in the comoving material frame.
    child.velocity = this->opacity->getRandomVelocity(cell);
    if(this->withHydro && !this->MMC)
    {
        LorentzTransformation(child, -1 * cell.velocity);
        ClampFrequencyToBounds(child.frequency);
    }

    particlesToAdd.push_back(child);

    if(!this->noHydroFeedback)
    {
        // Radiation source energy came from the material if signedEnergy > 0.
        // If signedEnergy < 0, an anti-packet was emitted and the material gains energy.
        this->conserved[cellIndex].internal_energy -= signedEnergy;
        if(this->withHydro)
        {
            // Follow the existing source convention in generateParticles.
            // For isotropic comoving emission the momentum source is the material bulk momentum, not child direction.
            const double gamma = (this->withHydro && !this->MMC)
                ? 1.0 / std::sqrt(1.0 - ScalarProd(cell.velocity, cell.velocity) * units::inv_clight2)
                : 1.0;
            this->conserved[cellIndex].energy -= signedEnergy * gamma;
            if(!this->diffusionPressureGradient)
            {
                this->conserved[cellIndex].momentum -= signedEnergy * cell.velocity * units::inv_clight2 * gamma;
            }
        }
    }
}
```

This helper uses signed energy. Do not reject negative `signedEnergy`.

### 5.2 `precomputeComptonData` in detail

Pseudo-code:

```cpp
void RadiationIMC::precomputeComptonData(double fullDt)
{
    const size_t N = this->grid.GetPointNo();
    this->comptonData.assign(N, ComptonCellData{});

    for(size_t i = 0; i < N; ++i)
    {
        const ComputationalCell3D& cell = this->cells[i];
        ComptonCellData& cd = this->comptonData[i];
        cd.active = true;
        cd.volume = this->grid.GetVolume(i);
        cd.temperature = cell.temperature;
        cd.Um = units::arad * boost::math::pow<4>(cell.temperature);

        // 1. Compute group absorption opacities and Planck fractions.
        cd.b = ComputePlanckFractions(cell);
        cd.kappaP = 0.0;
        for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
        {
            const double freq = energyGroupCenters[g];
            cd.kappa[g] = this->opacity->CalcAbsorptionOpacity(cell, freq);
            cd.kappaP += cd.kappa[g] * cd.b[g];
            cd.Eold[g] = cell.Eg[g] * cell.density;
        }
        this->planckOpacities[i] = cd.kappaP;

        // 2. Build qBase, the target distribution of ordinary IMC effective scattering.
        if(cd.kappaP > 0.0)
        {
            for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
                cd.qBase[g] = cd.kappa[g] * cd.b[g] / cd.kappaP;
        }
        cd.qBaseCdf = BuildCdf(cd.qBase);

        // 3. Build S and dSdUm using the deterministic routine port.
        BuildComptonMatricesForCell(cell, i, fullDt, /*calculate_n=*/this->comptonUseInduced, cd);

        // 4. Compute D[g], Upsilon, row sums, and Lambda.
        cd.Upsilon = 0.0;
        for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
        {
            cd.D[g] = 0.0;
            for(size_t h = 0; h < ENERGY_GROUPS_NUM; ++h)
                cd.D[g] += cd.dSdUm[h][g] * cd.Eold[h];
            cd.Upsilon += cd.D[g];
            cd.M[g] = cd.kappa[g] * cd.b[g] + cd.D[g];
        }
        for(size_t h = 0; h < ENERGY_GROUPS_NUM; ++h)
        {
            cd.rowS[h] = 0.0;
            for(size_t q = 0; q < ENERGY_GROUPS_NUM; ++q)
                cd.rowS[h] += cd.S[h][q];
            cd.Lambda[h] = cd.kappa[h] - cd.rowS[h];
        }

        // 5. Compute modified Fleck factor.
        cd.Gamma = cd.kappaP + cd.Upsilon;
        const double gammaLorentz = (this->withHydro && !this->MMC)
            ? 1.0 / std::sqrt(1.0 - ScalarProd(cell.velocity, cell.velocity) * units::inv_clight2)
            : 1.0;
        cd.cv = this->eos->dT2cv(cell.density, cell.temperature, cell.tracers, cell.tracerNames);
        cd.beta = 4.0 * units::arad * boost::math::pow<3>(cell.temperature) / cd.cv;
        const double cdtEff = units::clight * fullDt * gammaLorentz;
        const double denom = 1.0 + cd.beta * cdtEff * cd.Gamma;

        if(denom <= 0.0)
        {
            // Try n=0 fallback, matching deterministic code.
            if(this->comptonAllowNZeroFallback)
            {
                BuildComptonMatricesForCell(cell, i, fullDt, /*calculate_n=*/false, cd);
                cd.useNZero = true;
                // Recompute D, Upsilon, M, rowS, Lambda, Gamma, denom.
            }
            if(denom <= 0.0)
                throw UniversalError("Compton Fleck denominator is nonpositive; reduce dt or apply limiter");
        }

        cd.fleck = 1.0 / denom;
        this->factorFleck[i] = cd.fleck;
        cd.betaCdtF = cd.beta * cdtEff * cd.fleck;
        // For numerical consistency with the existing IMC effective scattering, you can also compute:
        // if(abs(cd.Gamma) > tiny) cd.betaCdtF = (1.0 - cd.fleck) / cd.Gamma;

        // 6. Build Kmat, Hbase, Sanalog, Sres, R, splits, and CDFs.
        BuildComptonResidualKernels(i, fullDt, cd);

        // 7. Build Bbase, Bcorr, and Btotal.
        BuildComptonSources(i, fullDt, cd);
    }
}
```

### 5.5 Analog direct Compton option

This option is recommended but can be implemented after the signed residual version works.

```cpp
void RadiationIMC::BuildAnalogDirectComptonMatrixAndCdfs(ComptonCellData& cd)
{
    Zero(cd.Sanalog);
    for(size_t h = 0; h < ENERGY_GROUPS_NUM; ++h)
    {
        std::array<double, ENERGY_GROUPS_NUM> targetRate{};
        double out = 0.0;
        for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
        {
            if(g == h)
                continue;  // same-group transitions do not change multigroup energy in the simple analog sampler
            const double rate = cd.tau[h][g] * (1.0 + n[g]);
            targetRate[g] = std::max(rate, 0.0);
            out += targetRate[g];

            const double ratio = energyGroupCenters[g] / energyGroupCenters[h];
            cd.Sanalog[h][g] += targetRate[g] * ratio;
        }
        cd.Sanalog[h][h] -= out;
        cd.directOutRate[h] = out;
        cd.directCdf[h] = BuildCdf(targetRate);
    }
}
```

The exact rate formula must match the same induced factors used in `S`. The residual `S - Sanalog` will correct any mismatch, including last-group boundary corrections. Therefore the analog sampler can start simple and become more accurate later without changing the expected linear operator.

```cpp
void RadiationIMC::EmitComptonResidualChildren(
    size_t cellIndex,
    const ComputationalCell3D& cell,
    size_t sourceGroup,
    const Vector3D& startLocation,
    const Vector3D& velocity,
    double startTimeLeft,
    double signedWeightAtStart,
    double alpha,
    double dt,
    double dopplerShift,
    std::vector<Particle>& particlesToAdd)
{
    const ComptonCellData& cd = this->comptonData[cellIndex];
    if(!cd.active)
        return;

    const double integratedWdt = IntegratedWeightOverDt(signedWeightAtStart, alpha, dt);
    const double rateFrameFactor = (this->withHydro && !this->MMC) ? dopplerShift : 1.0;
    const double pathEnergy = units::clight * rateFrameFactor * integratedWdt;

    const double rpos = cd.RposRow[sourceGroup];
    if(rpos > 0.0)
    {
        size_t target = SampleFromCdf(cd.RposCdf[sourceGroup], this->dist(this->re));
        const double tauBirth = SampleBirthTimeOnSegment(alpha, dt, this->dist(this->re));
        const Vector3D xBirth = startLocation + velocity * tauBirth;
        const double childTimeLeft = startTimeLeft - tauBirth;
        const double signedEnergy = pathEnergy * rpos;
        BankSignedChildPacket(cellIndex, cell, xBirth, velocity, childTimeLeft, target, signedEnergy, particlesToAdd);
    }

    const double rneg = cd.RnegRow[sourceGroup];
    if(rneg > 0.0)
    {
        size_t target = SampleFromCdf(cd.RnegCdf[sourceGroup], this->dist(this->re));
        const double tauBirth = SampleBirthTimeOnSegment(alpha, dt, this->dist(this->re));
        const Vector3D xBirth = startLocation + velocity * tauBirth;
        const double childTimeLeft = startTimeLeft - tauBirth;
        const double signedEnergy = -pathEnergy * rneg;
        BankSignedChildPacket(cellIndex, cell, xBirth, velocity, childTimeLeft, target, signedEnergy, particlesToAdd);
    }
}
```

```cpp
    // Otherwise use the existing scattering direction. The diffusion approximation does not retain the angular detail.
    particle.velocity = this->opacity->getNewScatterVelocity(cell, particle);

    particle.weight = newWeight;
    particle.frequency = FrequencyForGroup(targetGroup);

    if(!this->noHydroFeedback)
    {
        this->conserved[cellIndex].internal_energy += materialDeposit;
        if(this->withHydro && !this->diffusionPressureGradient)
        {
            this->conserved[cellIndex].momentum +=
                (oldWeight * oldVelocity - newWeight * particle.velocity) * units::inv_clight2;
        }
    }
}
```

With hydro and Lorentz transformations, this needs careful testing. Initially run Compton tests with `withHydro=false` or `MMC=true`. Once those pass, match the existing line 178-190 transformation convention.

## 8. Random walk interaction

The current `step` tries random walk before ordinary transport at lines 56-63. A random-walk step would skip residual source emission unless the random-walk estimator is extended.

For the first correct implementation:

- If `withCompton && comptonDisableRandomWalk`, skip random walk entirely.
- Or mark a cell ineligible for random walk if any of these are nonzero:
  - `sum_h RposRow[h]`
  - `sum_h RnegRow[h]`
  - direct Compton out rate
  - significant `Btotal` signed source

Implementation in `preStep` after `precomputeRandomWalkData()`:

```cpp
if(this->withCompton && this->comptonDisableRandomWalk)
{
    std::fill(this->rwCellEligible.begin(), this->rwCellEligible.end(), false);
}
```

Later, if random walk is needed with Compton, add a path-length estimator inside `tryRandomWalkStep` and emit residual children based on the expected path length of the random walk. Do not enable random walk with Compton before that estimator exists.

## 9. Post-step and cancellation

### 9.1 Signed tallies

`postStep` already sums `particle.weight` into `conserved.Erad` and `conserved.Eg` at lines 315-324. This is correct for signed packets.

Add diagnostics after the tally:

```cpp
for(size_t i = 0; i < Ncells; ++i)
{
    if(this->conserved[i].Erad < -radiationNegativeTolerance)
    {
        UniversalError eo("Negative radiation energy after signed Compton IMC tally");
        eo.addEntry("cell", i);
        eo.addEntry("Erad", this->conserved[i].Erad);
        throw eo;
    }
    if(this->multigroupOpacity)
    {
        for(size_t g = 0; g < ENERGY_GROUPS_NUM; ++g)
        {
            if(this->conserved[i].Eg[g] < -groupRadiationNegativeTolerance)
            {
                // Throw or log; do not silently clip in production tests.
            }
        }
    }
}
```

Use tolerances proportional to total absolute packet energy in the cell, not a hard-coded absolute number.

### 9.2 Packet cancellation

Signed residual packets can increase variance. Add a cancellation pass before final tallies or at census.

Primitive cancellation:

1. Group packets by `(cellIndex, group)`.
2. Sum signed weights in each bin.
3. Replace all packets in the bin by one packet if angular information is not important, or by a small fixed number of packets with representative directions.

Safer cancellation:

1. Separate positive and negative packets in the same `(cellIndex, group)`.
2. Sort by location or distance to cell center.
3. Cancel pairs by reducing the smaller absolute weight.
4. Remove zero-weight packets.

Do not alter material energy during radiation packet cancellation. Positive and negative radiation packets cancel each other; material was already updated when they were created or absorbed.

Add cancellation only after the basic scheme passes conservation tests, because cancellation can hide bugs.

## 10. Conservation rules

Every code path must obey these signed conservation rules.

### 10.1 Material source emission

When creating a signed radiation source packet with energy `Wemit`:

```cpp
material_internal_energy -= Wemit;
```

If `Wemit > 0`, material loses energy. If `Wemit < 0`, material gains energy.

### 10.2 Continuous absorption

Current line 128:

```cpp
material_internal_energy += -expm1(-alpha * dt) * particle.weight;
```

This is correct for signed packets. Absorbing a negative packet removes material energy.

### 10.3 Low-weight packet removal

When a remaining signed packet is killed and deposited locally:

```cpp
material_internal_energy += particle.weight;
```

This is already done at line 151. It is correct for signed packets.

### 10.4 Residual child packet emission

When `EmitComptonResidualChildren` creates a child of signed energy `Wchild`:

```cpp
material_internal_energy -= Wchild;
```

Do this in `BankSignedChildPacket`.

### 10.5 Physical analog Compton event

If an analog Compton event changes a packet from signed energy `Wold` to `Wnew`:

```cpp
material_internal_energy += Wold - Wnew;
```

For a positive photon that upscatters, `Wnew > Wold`, so the material loses energy. For a positive photon that downscatters, the material gains energy. For an anti-packet, the signs reverse automatically.

## 11. Unit conventions and consistency traps

The current IMC code appears to use unscaled physical units directly, while `MultigroupDiffusion.cpp` contains many `mass_scale_`, `length_scale_`, and `time_scale_` conversions. Do not blindly copy those scale factors into `RadiationIMC.cpp` unless the IMC class uses the same nondimensional convention.

Use these rules:

1. `particle.weight` is total radiation energy in the code's current energy units.
2. `cell.Eg[g] * cell.density` is group radiation energy density in the same units used by opacity and material coupling.
3. `grid.GetVolume(i)` is the volume in the same length units used by opacities.
4. `kappa`, `S`, `dSdUm`, `Kmat`, `Hbase`, and `R` must all behave like opacities: multiplying by `c * dt` gives a dimensionless interaction strength.
5. `Btotal[g]` must be total energy emitted in the cell over the time step, so it includes `V * c * dt`.

After implementation, add debug prints for one cell comparing:

```cpp
sum_g Bbase[g]
sum_g Bcorr[g]
sum_g Btotal[g]
V * c * dt * f * kappaP * Um
```

When Compton is disabled or `dSdUm = 0` and `S = 0`, `Bcorr` should be zero and `sum_g Bbase[g]` should match the old source energy from line 367.

## 12. Parity checks against deterministic matrix assembly

Add a debug-only function:

```cpp
void RadiationIMC::CheckComptonCoefficientParity(size_t i, double fullDt) const;
```

For a selected cell, reconstruct the matrix coefficient represented by the IMC kernels.

The IMC representation has base effective scattering `Hbase`, residual `R`, and analog direct `Sanalog`:

```math
K^{IMC}_{h\to g}=H^{base}_{h\to g}+R_{h\to g}+S^{analog}_{h\to g}.
```

By construction this should equal

```math
K^{target}_{h\to g}=K^{mat}_{h\to g}+S_{h\to g}.
```

Check:

```cpp
for h,g:
    assertNear(cd.Hbase[h][g] + cd.R[h][g] + cd.Sanalog[h][g],
               cd.Kmat[h][g] + cd.S[h][g]);
```

Also compare source:

```cpp
Btotal[g] == Bbase[g] + Bcorr[g]
```

To compare directly to deterministic `get_implicit_compton_contribution`, multiply opacities by `-V * c * dt` for left-hand-side matrix entries. The signs should match these identities:

```math
A^{implicit}_{g,h} = -V c\Delta t\left(H^{base}_{h\to g}+R_{h\to g}+S^{analog}_{h\to g}\right).
```

For no Compton, `R = 0`, `Sanalog = 0`, and `Hbase` should reduce to the ordinary IMC effective scattering already represented by the current code.

## 14. Common implementation errors to avoid

1. **Double-counting the thermal source.** If `generateComptonParticles` emits `Btotal`, do not also run the old line-367 source logic.

2. **Using the wrong target distribution for base effective scattering.** The residual subtracts `Hbase`. `Hbase` must use the exact same `q_g` that the effective scattering event samples. Prefer an explicit `qBaseCdf` built from `kappa_g*b_g/kappaP`.

3. **Raw negative-weight removal.** Any check like `weight < threshold` will instantly delete anti-packets. Use `abs(weight)`.

4. **Forgetting to update material for residual child emission.** Every signed child source has a material energy change `-Wchild`.

5. **Clipping negative residuals to zero.** This changes the linearized physics. Split into `Rpos` and `Rneg`; do not discard `Rneg`.

6. **Letting a nonpositive Fleck denominator through.** The signed split fixes negative event probabilities, not an invalid linearization. If `1 + beta*c*dt*Gamma <= 0`, reject the step, reduce `dt`, or apply the deterministic limiter/fallback.

7. **Using new-state temperatures.** All Compton matrices, derivatives, Planck fractions, and opacities in this scheme are frozen at the beginning of the step.

8. **Random walk skipping residual sources.** Disable random walk for Compton-active cells until a residual track-length estimator is implemented inside random walk.

9. **Double-counting electron scattering.** If `CalcScatteringOpacity` already represents the same electron scattering that `tau` represents, do not also add analog Compton collision opacity without subtracting/replacing the elastic component.

10. **Treating direct Compton weight changes as nonconservative.** If a packet changes group energy by a ratio, update material by `Wold - Wnew`.

## 17. Final notes on the two valid implementation modes

There are two valid ways to implement direct Compton in this framework.

### Mode 1: residual-only direct Compton

Set `comptonUseAnalogDirect=false`.

Then

```math
S^{analog}=0,
\qquad
S^{res}=S,
\qquad
R=K^{mat}-H^{base}+S.
```

Advantages:

- Fastest to code.
- Algebraically exact for the linearized multigroup equation in expectation.
- No risk of double-counting `CalcScatteringOpacity`.

Disadvantages:

- Direct Compton is represented through signed branch sources rather than physical collisions.
- May have higher variance.

### Mode 2: physical analog direct Compton plus residual correction

Set `comptonUseAnalogDirect=true`.

Then

```math
S^{res}=S-S^{analog},
\qquad
R=K^{mat}-H^{base}+S^{res}.
```

Advantages:

- Physical Compton group changes are sampled as positive events.
- Lower variance when `Sanalog` closely matches `S`.
- The residual still guarantees exact parity with the deterministic linearized operator.

Disadvantages:

- Requires careful event-rate and material energy-exchange implementation.
- Requires avoiding double counting with existing elastic/electron scattering opacity.

Recommended path: implement Mode 1 first, verify the implicit scheme, then add Mode 2 as an optimization.
