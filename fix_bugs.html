1. Scope and caveat

Important: the GitHub connector exposed the default branch at commit df95ff46531f4220f90f7f5f109fb8c2c13aef4d. No new pull request or feature-branch ref was visible. This review therefore applies to that snapshot. Before changing code, confirm that the working branch contains the same implementation or re-map the findings to the new files.

The primary files reviewed were:

  • radiation/RadiationIMC.hpp
  • radiation/RadiationIMCParameters.hpp
  • radiation/RadiationOpacityModel.hpp
  • particle/Particle.hpp
  • examples/moving_slab/main.cpp

Reference behavior was compared against the advanced DDMC implementation in eladtan/RICH_temp, especially source/3D/radiation/RadiationIMC_DDMC.cpp.

2. Release decision

Block release

The reviewed code is a simplified DDMC accelerator, not a correct implementation of the integration plan. Scientific use should be blocked until resident DDMC state, conservative face coefficients, cross-rank metadata exchange, interface treatment, and validation are implemented.

Highest-risk failure modes:

  • DDMC residence is lost after a leakage event.
  • Leakage coefficients are incorrect even on equal regular cells.
  • Cross-rank face coefficients can differ on opposite sides of the same face.
  • Boundary faces are omitted from the DDMC event process.
  • Multigroup DDMC uses nonphysical uniform group weights.
  • Static and moving IMC-DDMC interface algorithms are absent.

4. Detailed findings and fixes

F-01 — DDMC packets are not resident

Critical

Observed behavior

  • Particle has no DDMC-mode or resident-cell state.
  • Admission is recalculated from distance to the nearest face.
  • Leakage places the packet exactly at the face center.
  • The next DDMC admission check therefore sees approximately zero distance and usually fails.

Likely consequence

Multi-cell diffusion becomes a sequence of one DDMC hop followed by ordinary IMC transport. This changes the stochastic process, destroys intended acceleration, and can bias interface behavior.

Required fix

Add compact transport state to Particle or to a dedicated embedded structure:

struct RadiationTransportState {
    uint32_t flags = 0;              // DDMC resident, comoving, pending flux, etc.
    std::size_t ddmcCellID = invalid_id;
    std::size_t ddmcBypassCellID = invalid_id;
    PointT pendingFluxContribution{};
    double pendingPolarizationScatterings = 0.0;
};
  • A resident packet must remain directionless while traveling DDMC-to-DDMC.
  • Do not reapply the geometric particle-depth gate to resident packets.
  • Exit residence only at a DDMC-to-transport interface, unsupported boundary, invalid state, or explicit census handling.
  • Serialize every new field in two-sided MPI paths.
  • For raw RDMA transport, add layout assertions and a startup layout fingerprint check.

Acceptance tests

  • A packet performs at least ten consecutive DDMC-to-DDMC leaks without entering ordinary IMC.
  • Serial and two-rank trajectories have statistically identical residence counts.
  • Serialized and RDMA-transferred packets preserve all DDMC state exactly.

F-02 — Leakage coefficient is mathematically incorrect

Critical

The current construction effectively uses a harmonic mean and one center-to-face distance:

D_face = harmonic_mean(D_i, D_j);
lambda_i_to_j = D_face * A_face / (V_i * d_iF);

Use the conservative two-sided finite-volume resistance instead:

R_ij = d_iF / D_i + d_jF / D_j;
T_ij = A_face / R_ij;
lambda_i_to_j = T_ij / V_i;
lambda_j_to_i = T_ij / V_j;
For two equal cells, the reviewed implementation is larger by a factor of two. On distorted cells, it can also violate reciprocity.

Required implementation details

  • Compute both cell-center-to-face distances with consistent outward normals.
  • Reject nonfinite or nonpositive distances and diffusion coefficients.
  • Construct one shared conductance per physical face.
  • Store enough information to verify V_i * lambda_i_to_j == V_j * lambda_j_to_i.
  • Record the conductance and both directional rates in debug diagnostics.

Acceptance tests

  • Equal-cell analytic coefficient matches to near machine precision.
  • Local distorted-face reciprocity error is below a configured tolerance.
  • Cross-rank reciprocity is checked after metadata exchange.

F-03 — Cross-rank DDMC metadata is incomplete

Critical

Face construction uses remote data only when the neighbor index is locally addressable. Otherwise, source-cell values are reused. Opposite ranks can therefore construct different coefficients for the same physical face.

Metadata to exchange before face construction

  • stable cell ID
  • DDMC eligibility
  • all diffusion and opacity coefficients
  • group cutoff
  • cell velocity and divergence
  • cell volume
  • center-to-face distance, or sufficient geometry to compute it consistently
  • interface and exclusion flags

Recommended design

struct DDMCGhostCell {
    uint64_t stableID;
    bool eligible;
    double volume;
    double sigmaEnergyAbs;
    double sigmaMomentum;
    double sigmaDiffusion;
    double sigmaParticleGate;
    double sigmaGroupExit;
    double diffusionCoefficient;
    uint32_t groupCutoff;
    PointT velocity;
    double velocityDivergence;
};

Use a DDMC-specific symmetric exchange first. Do not rewrite the generic exchange framework until the DDMC path is correct. Ensure correspondence lists remain symmetric when a rank owns zero cells.

Acceptance tests

  • A face split across ranks yields identical conductance on both sides.
  • A rank with zero owned cells participates without deadlock.
  • Results are invariant under a different partition of the same mesh.

F-04 — Boundary faces are omitted from the DDMC event process

Critical

Boundary neighbors are skipped during precomputation. This removes escape, reflection, and prescribed-boundary channels from the total event rate.

Required fix

Introduce explicit face kinds:

enum class DDMCFaceKind {
    DDMCNeighbor,
    TransportNeighbor,
    ReflectingBoundary,
    EscapeBoundary,
    ThermalizingBoundary,
    UnsupportedBoundary
};

Each face record should hold:

  • kind
  • face index and stable target ID
  • DDMC leakage rate
  • transport-interface rate or admission data
  • boundary action data
  • outward unit normal
  • face area and both face distances

Acceptance tests

  • Reflecting DDMC boundary conserves energy and returns no net normal current.
  • Escape boundary produces the expected leakage probability.
  • Unsupported boundary fails early with a clear configuration error.

F-05 — Multigroup DDMC uses nonphysical uniform weights

High

Group weights are currently set to 1 / NumGroups, independent of temperature and group width. The code then sets gamma = 1, disabling the cutoff-crossing event.

Required fix

  • Compute Planck mass per group from frozen temperature and energy boundaries.
  • Normalize only over valid finite group masses.
  • Use distinct opacity roles rather than one overloaded sigmaA/sigmaT pair.
  • Compute the Densmore grey-band means and a physically meaningful group-exit coefficient.
  • Implement the analytic cutoff-crossing event.

Suggested cell data:

struct DDMCCellData {
    bool eligible;
    uint32_t groupCutoff;
    double sigmaEnergyAbs;
    double sigmaMomentum;
    double sigmaDiffusion;
    double sigmaParticleGate;
    double sigmaGroupExit;
    double diffusionCoefficient;
    double groupExitRate;
    double velocityDivergence;
    std::vector<DDMCFaceLeak> faces;
};

Acceptance tests

  • Planck masses sum to one within tolerance.
  • Changing temperature changes the grey-band coefficients.
  • Cutoff-crossing events occur in a case where the analytic rate is nonzero.

F-06 — IMC-DDMC interface treatment is missing

High

The current code treats every interior face as a generic leakage face and always emits a cosine-law transport direction at the face. It does not distinguish DDMC-DDMC from DDMC-transport transitions.

Required interface states

  • IMC → DDMC: static admission or reflection decision.
  • DDMC → IMC: asymptotic angular emission and representation change.
  • DDMC → DDMC: remain resident and directionless.
  • Moving interface: apply Wollaeger correction only after static admission.

Moving-interface rules

  • Evaluate the correction using the correct outward normal velocity.
  • Use a high-resolution or exact-enough quadrature table for the angular factor.
  • Invalid or excessive correction factors must bypass DDMC, not silently become one.
  • Local corrected packets may split; remote-target handling must remain unbiased without assuming local insertion.
  • Use a bypass stable cell ID to prevent immediate representation thrashing.

Acceptance tests

  • Static equilibrium-current test across an IMC-DDMC interface.
  • Admission/reflection probabilities match the reference formulation.
  • Moving-interface A/B test shows the expected correction trend.
  • Threshold sweeps at 3, 5, 10, 15, and 30 optical depths remain stable.

F-07 — Moving-medium frequency classification uses the wrong frame

High

Random-walk cutoff classification applies a Doppler transformation; DDMC cutoff classification does not. The DDMC path therefore compares a lab-frame frequency against a comoving-frame group cutoff.

Required fix

  • Define explicitly whether stored packet frequency is lab or comoving while resident.
  • Convert only at IMC-DDMC representation transitions.
  • Do not Lorentz-transform a newly sampled microscopic direction for ordinary DDMC-DDMC leakage.
  • Apply Doppler evolution from velocity divergence as a separate DDMC operator.

Acceptance tests

  • Homologous expansion produces the expected redshift.
  • Repeated DDMC-DDMC leakage produces no extra frame shift.
  • Near-cutoff classification is invariant under equivalent frame representations.

F-08 — Frequency-dependent scattering is ignored

High

The opacity interface provides CalcScatteringOpacity(cell, frequency), but transport and DDMC precomputation use only the grey overload.

Required fix

  • In multigroup IMC, evaluate scattering at the Doppler-shifted packet frequency.
  • In multigroup DDMC, compute the intended weighted scattering contribution for each opacity role.
  • Retain the grey overload only when multigroup transport is disabled.

Acceptance tests

  • A synthetic opacity with two strongly different group scattering values produces distinct interaction rates.
  • Grey mode remains unchanged when the frequency-dependent overload delegates to the grey value.

F-09 — Compton, postprocessing, and polarization remain placeholders

High

Parameters exist, but constructor validation rejects the features. ComptonCellData is empty, and packet state lacks signed weights, pending DDMC flux, bypass state, and pending accelerated-polarization history.

Required action

  • Do not advertise these features as implemented while they are rejected.
  • Keep Compton + DDMC a hard invalid combination until mathematically supported.
  • Implement Compton in dependency order: signed packets, frozen coefficients, matrix/Fleck terms, signed source, residual transport, parity, signed tallies/MPI, optional analog branch, variance controls.
  • Implement observer postprocessing separately from the transport core.
  • Preserve polarization scattering history across accelerated cells.

Acceptance tests

  • Feature-off behavior is unchanged.
  • Signed birth/death conserves material plus radiation energy.
  • Postprocessing does not feed back into hydro state.
  • Polarized Thomson tests preserve expected symmetries.

F-10 — Invalid DDMC geometry silently ends transport

Medium

If face selection fails or the face normal is invalid, the code marks the packet DONE. This loses the remaining census time without a physically valid event.

Required fix

  • Prefer a hard invariant failure with cell ID, face ID, rank, geometry, and coefficient diagnostics.
  • If a soft fallback is required, restore a valid IMC representation and preserve the remaining time.
  • Never translate geometry corruption into a census event.

F-11 — Parameter validation is incomplete

Medium

Add validation for

  • all group boundaries, including trait-provided boundaries
  • finite and strictly increasing boundaries
  • positive finite optical-depth thresholds
  • ddmcUseMultigroupPGRW requiring multigroup opacity
  • explicit policy for simultaneous RW and DDMC
  • Compton + DDMC hard rejection
  • postprocessing times and polarization parameters
  • nonzero finite timestep, volume, mass, heat capacity, and opacities where required
Current ordering tries random walk before DDMC. If both are enabled, random walk silently shadows DDMC in jointly eligible cells. Either reject the combination or define a documented deterministic selection policy.

F-12 — Validation coverage is insufficient

High

A moving-slab example is not a substitute for focused unit and regression tests. The integration should not merge on visual profile agreement alone.

See the complete test matrix in Section 7.

DDMC face data model

template<typename PointT>
struct DDMCFaceLeak {
    DDMCFaceKind kind;
    std::size_t faceIndex;
    std::size_t targetLocalIndex;
    std::uint64_t targetStableID;

    double conductance;
    double ddmcRate;
    double transportRate;
    double boundaryRate;

    double sourceFaceDistance;
    double targetFaceDistance;
    double targetCutoffEnergy;

    PointT outwardNormal;
};

Design rules

  • Freeze all DDMC coefficients in preStep.
  • Build faces only after ghost metadata exchange.
  • Keep DDMC residence independent of microscopic direction.
  • Separate energy absorption, momentum coupling, diffusion, particle gating, and group-exit opacity roles.
  • Every local and remote face should be classifiable without guessing from array bounds.
  • Feature-off behavior must remain unchanged.

7. Required validation matrix

Core DDMC mathematics

  • Equal-cell analytic conductance.
  • Distorted-cell reciprocity.
  • Constant radiation field remains constant.
  • Pure-scattering diffusion satisfies <r²> = 6Dt.
  • Absorption-only weight decay matches the analytic exponential.

Representation transitions

  • Ten or more consecutive DDMC-DDMC transitions preserve residence.
  • Static IMC-DDMC equilibrium current.
  • DDMC-to-IMC angular distribution.
  • Immediate re-entry prevention using bypass state.
  • Unsupported interface behavior fails deterministically.

Moving media

  • Homologous redshift.
  • No duplicate DDMC-DDMC Lorentz shift.
  • Moving-interface correction A/B comparison.
  • Correction threshold sweep at 3, 5, 10, 15, and 30.

MPI and transport backends

  • Two-rank cross-face reciprocity.
  • Zero-owned-cell rank.
  • Serial versus MPI statistical equivalence.
  • Two-sided manager.
  • MPI-RMA manager.
  • OFI manager.
  • IBV manager where available.
  • RDMA layout mismatch is detected at startup.

Regression applications

  • Marshak wave 1–4.
  • Densmore 2012 centered configuration.
  • Densmore 2012 exposed-interface configuration.
  • Moving-slab benchmark.
  • Feature-off runs match the pre-integration baseline within the chosen deterministic or statistical criterion.

Conservation

  • Material plus radiation energy ledger closes.
  • Cross-rank pending flux contributions are neither lost nor double-counted.
  • Momentum deposition agrees between serial and MPI decompositions.
  • Russian roulette and splitting preserve expectation.

8. Definition of done

  • All critical and high-severity findings in this document are closed or explicitly deferred with the corresponding feature disabled.
  • DDMC face reciprocity is checked in debug builds and passes locally and across ranks.
  • Packets remain resident across DDMC-DDMC transitions.
  • Boundary and transport-interface faces are explicit, not inferred from array bounds.
  • Multigroup coefficients use physical Planck masses and distinct opacity roles.
  • Moving-medium classification uses a documented frame convention.
  • Serial, two-sided, MPI-RMA, OFI, and IBV backends preserve packet state.
  • The required test matrix passes.
  • Unsupported features are rejected clearly and are not presented as implemented.
  • Performance and memory regressions are measured and documented.

9. Instructions for the fixing agent

  1. Resolve the exact branch and compare it with the reviewed commit before editing.
  2. Do not copy RICH managers, mesh types, or application-specific logic wholesale.
  3. Port the mathematics and state machine into STORM's generic abstractions.
  4. Keep each pull request small enough to review independently.
  5. Add tests in the same pull request as each behavior change.
  6. Do not silence invalid geometry or invalid moving-interface factors.
  7. Do not optimize until reciprocity, residence, conservation, and backend parity are established.
  8. When a requirement conflicts with current STORM behavior, document the conflict and preserve feature-off compatibility.
Recommended first implementation task: add packet residence state and a pure, unit-tested two-sided face-conductance helper. Those two changes expose most downstream assumptions and make later MPI and interface work reviewable.
Suggested code-review checklist for each patch
  • No hidden use of local indices as stable cross-rank IDs.
  • No face coefficient is constructed from source data alone when target data is required.
  • No packet state is omitted from serialization or raw transfer.
  • No invalid event is converted into DONE.
  • No DDMC-DDMC transition creates a physically meaningful microscopic direction.
  • No feature changes behavior when its flag is disabled.
