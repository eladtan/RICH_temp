STORM Compton Parity Handoff

Instructions for making STORM rich_features match the Compton implementation in RICH_temp ablation, instead of retaining STORM's current reduced external-kernel adapter.

1. Executive decision

STORM is not currently equivalent to RICH ablation Compton IMC. STORM accepts externally supplied frozen rates and optional correction vectors. RICH owns CMMC internally and derives the complete f-reduced operator, induced terms, source decomposition, event kernel, angular distribution, material coupling, risk controls, and end-of-step correction.

Use RICH ablation as the behavioral specification. The target normal workflow is: a user enables Compton in RadiationIMCParameters, supplies the ordinary EOS, opacity and cell data, then constructs RadiationIMC. STORM must build and use the CMMC matrices internally. No application-defined matrix builder is required.

2. Matrix ownership correction

The user's central observation is correct: matrix construction is not the caller's responsibility in RICH. The precise timing is important:

  • RICH stores std::unique_ptr<ComptonMatrixMC> comptonMatrixGen inside RadiationIMC.
  • The constructor stores parameters and validates combinations.
  • initializeComptonMatrixGenerator() lazily creates CMMC and its temperature tables from precomputeComptonData().
  • The Till MC application constructs RadiationIMC directly and never injects a matrix kernel.
Do not eagerly build expensive CMMC tables in the constructor if exact RICH behavior is required. Ownership is established by the class, but initialization is lazy at first Compton pre-step.

Remove as the normal STORM API

auto kernel = std::make_shared<TillComptonKernel>(...);
auto physics = std::make_shared<RadiationIMC<...>>(...);
physics->setComptonKernel(kernel);

Required normal API

RadiationIMCParameters<NumGroups> p;
p.withMultigroupOpacity = true;
p.withCompton = true;
p.comptonMatrixSamples = 2'000'000;
auto physics = std::make_shared<RadiationIMC<...>>(
    grid, boundary, cells, extensives, eos, opacity, p);
// No matrix object and no setComptonKernel().

3. Scope and caveats

  • This document compares the connector-visible current heads of STORM rich_features and RICH_temp ablation.
  • No compilation or runtime validation was possible in this environment.
  • The CMMC gitlink SHA was not exposed by the connector. Before implementation, pin STORM to the exact CMMC revision used by RICH ablation.
  • Exact parity includes RICH's present exclusions: Compton with random walk and Compton with DDMC are rejected.
  • Establish deterministic parity before refactoring, adding alternate kernels, or changing physics conventions.

5. Target architecture

Template/public side

  • radiation/RadiationIMCParameters.hpp
  • radiation/RadiationIMC.hpp
  • radiation/compton/ComptonTypes.hpp
  • Generic arrays and cell/packet algorithms.

CMMC integration side

  • radiation/compton/CMMCComptonBackend.hpp
  • radiation/compton/CMMCComptonBackend.cpp
  • Private CMMC includes, compiled source, stable typed wrapper.

A backend wrapper should expose tau matrices, derivatives, maximum table temperature, last-group correction, conditional angle CDF and angle-bin count. It should hide CMMC from STORM's public headers when possible.

std::unique_ptr<CMMCComptonBackend<NumGroups>> comptonMatrixGen_;

void initializeComptonMatrixGenerator() {
    if (comptonMatrixGen_) return;
    initializeComptonGroups();
    comptonMatrixGen_ = std::make_unique<CMMCComptonBackend<NumGroups>>(
        comptonGroupCenters_, energyBoundaries_,
        parameters_.comptonMatrixSamples, true, 1);
    comptonMatrixGen_->setTables(buildComptonTemperatures());
}

An injectable backend may remain as a private test seam, but it must not be required or documented for ordinary users.

7. Lifecycle and algorithms

7.1 Constructor

  1. Store parameters and validate grid/EOS/opacity.
  2. Require multigroup opacity for Compton.
  3. Reject Compton + random walk.
  4. Reject Compton + DDMC.
  5. Apply RICH postprocess/polarization compatibility rules.
  6. Validate energy boundaries.
  7. Do not require an injected kernel.
  8. Do not yet build expensive CMMC tables.

7.2 Lazy generator initialization

  1. Compute centers and widths.
  2. Build the RICH temperature grid: 0.0001, 0.001 and 0.005 keV plus 128 logarithmic points from 10^-2 to 10^4 keV.
  3. Construct CMMC with configured sample count, detailed balance enabled and the RICH deterministic seed.
  4. Call set_tables() once.

7.3 Per-cell precomputation

  1. Compute volume, temperature, Um=aT^4, heat capacity and beta=4aT^3/cv.
  2. Compute normalized Planck group fractions.
  3. Compute group absorption opacity and Planck opacity.
  4. Read old group radiation energy from the cell.
  5. Build base source fractions and safe CDFs.
  6. Build CMMC matrices using radiation-field occupation when induced terms are enabled, otherwise zero occupation.
  7. Compute contractions, Upsilon and Gamma.
  8. If the denominator is nonpositive or Upsilon<0, apply the same zero/Planck fallback decision as RICH and rebuild matrices.
  9. Compute Fleck, event data, source arrays and risk data.

Core equations

D[g]      = sum_h dSdUm[h][g] * oldRadiationEnergy[h]
Upsilon   = sum_g D[g]
M[g]      = absorptionOpacity[g] * planckFraction[g] + D[g]
rowS[h]   = sum_g S[h][g]
Lambda[h] = absorptionOpacity[h] - rowS[h]
Gamma     = planckOpacity + Upsilon
f         = 1 / (1 + beta * c * dt_eff * Gamma)

betaCdtF = beta * cdtEff * f
if (abs(Gamma) > tiny) betaCdtF = (1 - f) / Gamma

Matrix construction details

  • Compute occupation from radiation energy, Planck energy, or zero according to the selected mode.
  • Clamp occupation exactly as RICH.
  • Call CMMC get_tau_matrix() at a temperature capped below its maximum table value.
  • Apply CMMC's last-group up/down correction.
  • Build S and dSdUm with induced factors.
  • Scale the derivative by 1/(4aT^3).

8. Event transport parity

8.1 Event operator

weight[h->g] = max(0, tau[h][g] * (1 + occupation[g]))
outRate[h]   = sum_(g != h) weight[h->g]
q[h->g]      = weight[h->g] / outRate[h]
mu[h]        = sum_(g != h) q[h->g] * center[g] / center[h]
Mh[h]        = 1 + f * (mu[h] - 1)

Port buildComptonEventData() before attempting to simplify it. It constructs the base effective opacity, total physical kernel, explicit event segment and residual kernel.

8.2 Scatter event

  1. Sample target group from the internal CDF.
  2. If angle dependence is enabled, request CMMC's conditional angle CDF for temperature/source/target, sample a bin, interpolate within it, sample azimuth and rotate relative to the incoming direction.
  3. Otherwise use the ordinary direction sampler exactly as RICH does.
  4. Set newWeight=oldWeight*Mh[source].
  5. Set frequency to RICH's representative target-group center.
  6. Deposit oldWeight-newWeight to material internal/total energy.
  7. With hydro momentum feedback, deposit (oldWeight*oldVelocity-newWeight*newVelocity)*inv_c2.

8.3 Frame handling

Retain STORM's generic Lorentz helpers, but validate that the RICH event is evaluated in the material frame and transformed back exactly once. Add packet four-momentum closure tests.

Elastic opacity policy: RICH sets ordinary elastic scattering opacity to zero when Compton is active. STORM currently adds the channels. Exact parity requires the RICH policy. A later change may reconsider this only after parity is established and scientifically reviewed.

9. End-of-step correction and packet reconciliation

This is the largest missing subsystem. A caller-supplied residual source vector is not equivalent to RICH's state-dependent residual operator.

Required postStep() order

  1. Tally surviving packet energy into Erad and Eg[g].
  2. Record per-cell/group packet counts and maximum packet weights.
  3. Run applyComptonEndOfStepCorrection(fullDt).
  4. Run reconcileComptonParticles(particles).
  5. Apply opposite material correction and update thermodynamics.
  6. Run parity and signed diagnostics when enabled.

Solver stack to port

  • Direct group-system solve with pivot diagnostics.
  • Support-aware treatment of tiny negative groups.
  • Material-energy cap.
  • Bounded/NNLS fallback support and diagnostics.
  • Adaptive subcycling of the residual operator.
  • Early stop and return-to-raw endpoint when accepted correction is negligible.
  • Failure records with worst group, support fraction, risk score and packet support.

Energy update

deltaRadiation = sum_g(solvedEg[g] - rawEg[g]);
extensives.Eg[g] = solvedEg[g];
extensives.Erad += deltaRadiation;
if (!noHydroFeedback) {
    double materialDeposit = -deltaRadiation;
    extensives.internal_energy += materialDeposit;
    extensives.energy += materialDeposit;
}

Reconciliation requirements

  • Corrected cell/group energies must be represented by packet weights.
  • Preserve signed accounting.
  • Avoid one enormous packet in a weakly supported group.
  • Use risk/target packet counts.
  • After reconciliation, group packet sums must match corrected Eg within tolerance.

10. CMMC dependencies and CMake

10.1 Pin the authoritative revision

  • Read the CMMC gitlink SHA from RICH_temp ablation.
  • Pin STORM's deps/CMMC to the same SHA.
  • Verify APIs: set_tables, get_tau_matrix, maximum table temperature, last-group correction, get_angle_cdf, and NUM_ANGLE_BINS.
  • Expose the pinned revision in build diagnostics.

10.2 Make CMMC library-level

Current STORM builds compton_matrix_mc.cpp only into the Till example. Replace that with a library target used by RadiationIMC.

option(STORM_WITH_COMPTON "Build internal CMMC support" ON)
if(STORM_WITH_COMPTON)
  set(STORM_CMMC_DIR "${CMAKE_CURRENT_SOURCE_DIR}/deps/CMMC/src"
      CACHE PATH "Pinned CMMC source directory")
  if(NOT EXISTS "${STORM_CMMC_DIR}/compton_matrix_mc.cpp")
    message(FATAL_ERROR
      "Compton support requires the pinned CMMC submodule. "
      "Run git submodule update --init --recursive")
  endif()
  add_library(storm_cmmc STATIC
    "${STORM_CMMC_DIR}/compton_matrix_mc.cpp"
    radiation/compton/CMMCComptonBackend.cpp)
  target_include_directories(storm_cmmc PRIVATE "${STORM_CMMC_DIR}")
  target_link_libraries(storm_cmmc PUBLIC Boost::boost units planck_integral)
  target_link_libraries(storm INTERFACE storm_cmmc)
endif()

Adjust link visibility according to whether storm is a concrete or INTERFACE target. Do not use invalid PUBLIC operations on an INTERFACE library.

10.3 Clone/install behavior

  • Prefer an HTTPS CMMC submodule URL for public credential-free cloning.
  • Document git clone --recurse-submodules.
  • Update install_deps.sh to initialize the pinned submodule, not clone an unpinned head.
  • When Compton is requested and CMMC is missing, CMake must fail clearly rather than silently skip the regression.

10.4 Packaging

  • Keep CMMC includes private through the backend wrapper.
  • Verify Boost, units, planck_integral and math linkage.
  • Verify CMMC's license and required redistribution notices.
  • Test an installed STORM package from a clean consumer project.

11. Public API changes

Remove required injection

Deprecate or remove setComptonKernel() and getComptonKernel() from the normal public workflow. If retained for tests, name and document it as a testing/advanced seam.

Parameter parity

  • Add ComptonInducedMode.
  • After angle implementation, set comptonAngleDependent=true by default.
  • Reject Compton + random walk and Compton + DDMC during construction.
  • Keep comptonMatrixSamples: users control numerical effort, but not matrix construction.

Type contracts

  • Compton requires cell temperature and density.
  • EOS must supply heat capacity and material updates.
  • Cell/extensive state must supply group energies of length NumGroups.
  • Momentum coupling is enabled only when velocity and momentum members exist.
  • Fail explicitly when required Compton state is unavailable.

12. Till-Compton example changes

Delete example-local matrix ownership

Remove TillComptonKernel, its ComptonMatrixMC member, direct CMMC include, and the call to setComptonKernel() from examples/till_compton_mc/main.cpp.

Keep only problem data

The example should define energy boundaries, opacity, EOS, material state, mesh, boundary, population control, timestep and Compton parameters. It should instantiate RadiationIMC exactly like the RICH Till MC regression: constructor only, with no matrix object.

Make the regression authoritative

The current STORM checker verifies only that the run completed, a profile exists and an energy-drift value was printed. Replace that with:

  • temperature-curve error thresholds against a frozen RICH-ablation reference using identical seed, CMMC revision, sample count, packet count and timestep;
  • a strict total-energy drift threshold;
  • a minimum Compton-event count;
  • proof that induced mode and angle-dependent transport were exercised;
  • a clean-clone dependency/build test.

13.2 Event tests

  • Fixed RNG stream yields the same target groups as RICH.
  • Angle samples reproduce CMMC conditional CDFs.
  • Packet weight equals oldWeight*Mh.
  • Material energy is opposite to packet energy change.
  • Hydro momentum closes against packet momentum change.
  • Moving-frame event is transformed exactly once.

13.3 Source/correction tests

  • Btotal=Bbase+Bcorr.
  • Btotal=Bpos+Bres.
  • Positive source packet total equals Bbase.
  • Direct solve matches RICH for admissible cases.
  • Negative solution and material-cap cases select the same fallback.
  • Adaptive subcycling returns the same consumed fraction and endpoint.
  • Reconciliation reproduces corrected group energies.

13.4 Integrated regressions

  2. Winslow: hot material, cold radiation.
  3. Compton-only: no absorption.
  4. No-Compton control.
  5. Forced negative-Upsilon fallback.
  6. Moving-material energy and momentum closure.
  7. MPI global-ledger parity.

15. Definition of done

  • A normal application enables Compton through parameters only.
  • No example/application constructs ComptonMatrixMC.
  • No normal application calls setComptonKernel().
  • STORM owns one lazily initialized CMMC generator per RadiationIMC.
  • STORM pins the same CMMC revision and table grid as RICH ablation.
  • All derived matrices/arrays match deterministic RICH references.
  • Induced mode and zero/Planck fallback match RICH.
  • Compton-modified Fleck matches RICH.
  • Positive source, event, residual solve and reconciliation are present.
  • Angle-dependent sampling is implemented and enabled by default.
  • Event energy and momentum coupling match RICH.
  • Compton + RW and Compton + DDMC are rejected.
  • Till and Winslow meet numerical thresholds.
  • Serial/MPI global energy ledgers close within declared tolerance.
  • Clean cloning/building requires one documented submodule command.
  • CMake fails clearly when requested CMMC is missing.
